# 독립 챗봇 이용·초기화 정책

기준: [전체 안내](../README.md) · 연계: [기획·UX](service.md), [프론트](../frontend/application.md), [API](../backend/api.md), [DB](../data/database.md), [AI·RAG](../ai/rag.md), [QA](../quality/verification.md)

## 1. 기능 범위

| 요구사항 | 동작 |
| --- | --- |
| 사용자가 챗봇 세션 초기화 | 챗봇 화면의 ‘대화 초기화’로 현재 대화를 종료하고 빈 새 대화를 시작한다. |
| 간단 설문과 챗봇 분리 | 로그인 후 바로 질문한다. 설문 작성·완료는 필수가 아니며 자동 공유하지 않는다. 사용자가 본인 설문 결과를 골라 불러오면 그 입력만 현재 대화에 복사한다. |
| 웹사이트 안에서 답변 처리 | 질문 접수·추가 확인·답변·근거 확인을 챗봇 화면에서 마친다. 링크 방문이나 설문 화면 이동을 답변 확인의 필수 단계로 삼지 않는다. |

회원 전용 권한, 내부 RAG 선행, 근거 없는 판단 금지, 연락처 없는 직접 문의, 실제 접수·승인·비용 확정 제외 정책을 적용한다. 생성·저장·한도는 [챗봇 생성 계약](../ai/chat-generation.md)을 따른다.

## 2. 독립된 이용 흐름

- 설문: 홈 → 주택·증상 선택 → 간단 설문 → 안내 결과.
- 챗봇: 홈 또는 상단 메뉴 → 로그인(필요 시) → 챗봇 → 질문·추가 확인·답변.
- 결과 화면에서 챗봇으로 이동해도 설문 세션 ID·선택·답변·결과를 전달하지 않는다. 유효한 본인 챗봇 세션이 있으면 그 대화를 복원하고, 없으면 빈 대화를 시작한다.

설문과 챗봇은 서로 다른 세션 ID·맥락·revision·처리 중 요청·브라우저 복구 정보를 사용한다. 사용자가 ‘이전 설문 불러오기’에서 본인 결과를 고르고 ‘선택한 설문 불러오기’를 누를 때만 주택·위치·증상·답변을 복사한다. 자유 입력 추가 설명과 과거 안내 결론·대화는 복사하지 않는다. 다음 질문부터 검토된 선택/답변 라벨을 외부 제공자에 전달함을 불러오기 전에 설명한다. 이후 설문 수정·종료·삭제가 복사본에 자동 반영되지는 않으며 챗봇 초기화는 설문과 결과 이력에 영향을 주지 않는다.

챗봇에서 정보가 더 필요하면 같은 대화에서 확인 질문을 하고 사용자가 채팅으로 답한다. 주택·시설물·증상은 해당 질문에 필요한 경우에만 확인한다. 조문 설명에 불필요한 주택 선택이나 설문 필수 답 때문에 답변을 막지 않는다. 질문에 필요한 조건이 모자라면 CLARIFY·NEED_MORE_INFO로 처리하고, 확인되지 않은 조건을 임의로 채우지 않는다. 지원 범위와 안전 확인은 챗봇에서 확인한 정보에 적용한다.

지원 주택과 관찰된 증상을 알면 원인 시설을 특정하지 못해도 증상으로 참고 자료를 찾는다. 거실 천장에서 물이 보인다면 누수 자료와 문의할 내용을 안내하고, 원인 시설을 확인하기 전까지 참고 자료를 바탕으로 보수 대상이나 비용을 판단하지 않는다.

## 3. 대화 초기화

PC에서는 대화 옆에 확인한 내용과 ‘대화 초기화’를 배치한다. 모바일에서는 ‘대화 정보’로 같은 메뉴를 펼친다. ‘이전 설문 불러오기’는 입력창 옆에서 제공한다. Enter는 전송, Shift+Enter는 줄바꿈이며 한글을 조합 중이면 전송하지 않는다.

초기화 확인 화면에는 ‘현재 대화와 챗봇에서 확인한 내용이 지워지고 새 대화를 시작합니다. 설문·결과 이력과 별도 보존되는 질문 분석 기록은 유지됩니다.’라고 설명하며 취소·초기화를 선택할 수 있게 한다.

1. 전송·응답 복구·초기화 중에는 초기화 버튼을 비활성화한다. 다른 탭의 요청으로 SESSION_BUSY가 발생하면 기존 대화를 유지하고 처리 종료 후 다시 시도하도록 알린다.
2. 본인 CHAT 세션을 기존 `DELETE /sessions/{id}`로 종료한다. 서버는 현재 대화·맥락·단기 요청/응답을 정리한다. 삭제 성공 전에는 빈 대화로 바꾸거나 새 세션을 만들지 않는다.
3. 삭제 성공 후 이전 챗봇 세션 ID·입력 초안·대화 캐시·처리 중 requestId를 지우고 `POST /sessions`의 `purpose=CHAT`으로 새 세션을 만든다. 새 ID·revision=0·빈 맥락으로 시작하며 이전 메시지를 검색·생성 입력에 넣지 않는다.
4. 삭제가 실패하면 기존 대화와 세션을 유지하고 오류를 알린다. 삭제 응답이 유실되면 기존 세션을 조회해 종료 여부부터 확인한다. 유효한 본인 인증에서 기존 세션이 더 이상 없으면 종료된 것으로 처리한다.
5. 삭제는 성공했지만 새 세션 생성이 실패하면 빈 화면에 ‘새 대화를 시작하지 못했어요. 다시 시도해 주세요.’를 표시한다. 재시도는 새 세션 생성만 수행하며 종료한 대화를 복원하지 않는다.

새 세션으로 전환한 뒤 늦게 도착한 이전 세션 응답은 무시한다. 다른 탭의 이전 세션도 다음 조회·전송에서 종료 상태를 감지하면 챗봇 캐시를 지우며 자동으로 이전 질문을 재전송하지 않는다. 챗봇 초기화는 로그인 상태·설문 세션·저장된 설문 결과·회원 이력·회원/서비스 사용량 한도를 바꾸지 않는다.

초기화는 현재 챗봇 대화 종료다. 장기 정제 질문은 기존 보존 정책대로 유지하며 전체 개인정보 삭제로 표현하지 않는다. 질문 분석 기록 삭제는 기존 회원 기록 삭제 기능으로 제공한다. 상담 삭제 기록과 백업 복원 후 재삭제는 기존 삭제 절차를 따른다.

## 4. 웹사이트 내 답변과 근거 표시

챗봇 말풍선에 질문에 대한 답변, 적용 조건·주의사항 또는 확인 질문을 직접 표시한다. ‘자세한 내용은 링크를 확인하세요’나 URL만으로 답변을 대신하지 않는다. 근거가 부족하거나 장애가 생겨도 이유와 확인할 내용을 같은 화면의 TEMPLATE·CLARIFY 응답으로 보여준다. 담당 기관의 실제 판단이 필요한 경우 직접 문의할 내용을 화면에 제공하며 실제 보수 접수 기능은 추가하지 않는다.

챗봇과 설문은 검색한 법령에 대응하는 쉬운 설명을 먼저 표시한다. 설명 바로 아래의 ‘근거 보기’에서 조문·별표 원문, 시행일, 검토 정보와 공식 원문 링크를 확인할 수 있다. 원문 링크를 누르지 않아도 답변과 근거를 이해할 수 있어야 한다. 입력 URL 방문·외부 검색은 수행하지 않는다.

쉬운 설명은 검색된 조문·별표와 정확히 일치하는 원문 해시에 연결한 편집 문구를 사용한다. 법령상 확인할 점을 안내하고 실제 보수 가능 여부·비용·기간은 적격 운영 근거를 기준으로 판단한다. 생성 모델의 법령·운영 근거 검증은 [생성·검증 범위](../ai/chat-generation.md#생성검증-범위)를 따른다.

정보가 부족한 운영 문의의 TEMPLATE·CLARIFY 응답에는 최대 2개의 편집된 가상 보수 검토 예시를 별도 표시한다. 선택한 증상과 검토된 설문 항목을 활용하며 시설물·증상을 모두 특정하지 못하면 ‘일반 예시’라고 명시한다. 시설물만 알고 증상을 특정하지 못하면 무관한 예시를 억지로 붙이지 않는다. 실제 처리 이력·하자 판정·승인 근거로 표현하지 않고, 문의·추가 확인 안내를 유지한다. 법령 설명·위험 우선·범위 밖 주택·적용 근거가 확보된 안내와 `GUIDANCE_UNAVAILABLE` 응답에는 붙이지 않는다. 가스·전기 설비·소방·승강기·난간·옹벽의 일반 보수 예시도 제외한다. 예시를 생성 모델이나 검색에 넣지 않는다.

## 5. 계약과 데이터 경계

세션·브라우저·저장의 계약은 다음과 같다. API·DB 변경은 [계약 변경 규칙](../development/standards.md#5-계약과-스키마-변경)을 따른다.

| 영역 | 계약 |
| --- | --- |
| 세션 생성·응답 | `purpose: SURVEY 또는 CHAT`. 생성 요청에서 생략하면 기존 호환용 SURVEY이며 챗봇은 CHAT을 명시한다. CHAT 생성은 로그인 계정만 허용한다. 기존 catalogVersion·knowledgeReleaseId 고정 정책을 재사용한다. |
| 입력·요청 검증 | 설문 질문·평가는 SURVEY, 새 채팅/설문 불러오기는 CHAT에서만 허용한다. 용도가 다르면 409 SESSION_PURPOSE_MISMATCH다. CHAT은 대화 확인 값과 명시적으로 불러온 유효한 설문 답변을 담는다. 일반 context PUT으로 답변을 주입할 수 없으며 설문 required 규칙으로 대화를 막지 않는다. 불러온 위험 답변은 안전 우선이며 선택이 달라지면 복사 답변을 비운다. |
| 초기화 | 별도 초기화 API 없이 기존 세션 종료 → CHAT 세션 생성 순서를 사용한다. 삭제·생성 각각의 실패와 응답 유실을 구분한다. |
| DB | consultations.purpose의 기본값·허용값 CHECK로 용도를 제한한다. 기존 상담은 SURVEY로 분류한다. 기존 공유 상담의 완료 CHAT 이력은 본인에게 과거 기록으로만 조회하도록 보존하고 새 전송에는 독립 CHAT 세션을 요구한다. 입력 복사는 본인 결과의 명시적 불러오기 API로만 수행한다. 새 DB 필드는 추가하지 않는다. |
| 브라우저 | surveySessionId와 chatSessionId 및 요청 복구 키를 구분하고 Query 키에도 계정·용도·세션 ID를 포함한다. 계정 변경·로그아웃 시 양쪽의 사용자별 캐시를 제거한다. |
| 답변 근거 | 챗봇 인용에 사이트 내 표시용 `excerpt`를 제공한다. 서버가 검토된 원문과 필요한 조건·단서에서 구성하며 모델 문자열을 그대로 쓰지 않는다. 기존 설문/과거 응답과의 호환을 위해 Citation의 필드는 선택적으로 추가하되 새 근거 기반 채팅에는 제공한다. |

DTO·OpenAPI·생성 프론트 타입·DB migration·화면·회귀 검증을 함께 반영한다. 인수는 [검증 기준](../quality/verification.md)의 F28~F34와 기존 기능 회귀를 함께 확인한다.

## 6. 인수 기준

- 설문을 한 번도 작성하지 않은 회원이 챗봇에서 바로 질문하고 필요한 내용을 같은 대화에서 확인할 수 있다.
- 설문 답·결과를 바꾸어도 챗봇 입력과 답변 맥락에 자동 반영되지 않는다.
- 초기화 취소는 기존 대화를 유지하고, 성공 후에는 새 세션과 빈 대화가 새로고침 뒤에도 유지된다.
- 초기화 실패·다른 탭의 처리 중 요청·응답 유실·새 세션 생성 실패를 구분하며 이전 답변이 새 대화에 섞이지 않는다.
- 초기화 후에도 로그인·설문·회원 결과 이력·사용량 한도가 유지되고, 장기 질문 보존 범위가 화면 설명과 일치한다.
- 외부 링크를 열지 않아도 답변과 근거를 사이트 안에서 확인할 수 있다. 링크만 반환하거나 설문 작성으로 넘기는 응답은 인수 실패다.
- 권한·RAG·위험 우선순위·근거 부족 안내·삭제/복원·중복 방지 회귀 검증을 통과한다.
