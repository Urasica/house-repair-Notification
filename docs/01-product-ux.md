# 기획·UX 역할 설계

상위 문서: [전체 안내](README.md) · 연계: [프론트](02-frontend.md), [API](03-backend.md), [AI·RAG](05-ai-rag.md)

## 1. 책임과 서비스 범위

기획·UX는 지원 주택, 완성된 증상·질문 목록의 의미, 로그인별 권한, 결과 문구와 근거 적용 범위를 정한다. 현재 문서의 기술 예시를 실제 증상 목록으로 게시하지 않는다.

지원 대상은 LH 건설임대주택과 분양전환형 주택의 임대 거주 기간이다. 실제 보수 접수·승인·비용 확정·현장 진단은 제공하지 않는다. 계정·챗봇·이전 결과 조회는 이번 범위에 포함한다.

## 2. 이용 권한과 결과 저장

| 이용 상태 | 가능 | 불가 |
| --- | --- | --- |
| 비로그인 | 간단 설문, 현재 결과·근거·문의 문구 보기; 결과 서버 저장 | 챗봇 이용, 과거 결과 목록·만료 결과 재조회 |
| 로그인 | 설문, 챗봇, 본인의 이전 결과 목록·상세, 기록 삭제 | 다른 계정 결과 보기 |

비로그인 상태의 챗봇 버튼은 로그인 안내를 표시한다. 입력창만 숨기는 방식으로 접근을 제어하지 않으며 서버도 차단한다. 로그인에는 이메일·비밀번호를 사용하고 주택 주소·동호수·전화번호는 필수 정보로 요구하지 않는다.

결과 저장은 설문 평가 성공 시 서버에서 자동 수행한다. 회원은 별도 저장 버튼 없이 계정 이력에 연결한다. 비회원은 현재 익명 세션에만 연결한다. **회원 이력에는 로그인한 상태에서 생성한 결과만 포함한다.** 비회원 상담 중 로그인하면 새 회원 상담을 시작하며 기존 익명 결과를 계정에 옮기는 기능은 초기 범위에서 제외한다.

로그아웃하면 브라우저의 계정 이력·챗봇 캐시를 지운다. 서버에 저장된 회원 이력은 유지한다. 공유 기기에서 이전 사용자의 결과가 표시되지 않도록 한다. 새 비로그인 상담은 별도 익명 세션으로 시작한다.

## 3. 화면 구성

| 화면·경로 | 구성·행동 |
| --- | --- |
| 홈 `/` | 서비스 소개, 비로그인 설문 시작, 로그인, 회원 챗봇·이력 진입 |
| 주택·증상 `/select` | 게시된 주택·공간·시설물·증상 선택, 요약 |
| 간단 설문 `/survey` | 서버가 반환한 선택형 질문, 모름 값, 저장·결과 보기 |
| 챗봇 `/chat` | 회원 전용 대화, 맥락 확인, 근거 표시 |
| 현재 결과 `/result/:resultId` | 상태·요약·관련 근거·문의 문구, 회원 이력 연결 여부 |
| 로그인·가입 `/login` | 이메일·비밀번호, 로그인·가입 전환, 원래 화면 복귀 |
| 이전 결과 `/history` | 회원 본인 결과 목록, 날짜·증상 요약·결과 상태 |
| 이전 결과 상세 `/history/:resultId` | 생성 당시 기록, 현재 적용 가능 여부, 새 상담·삭제 |

핵심 5개 화면의 기존 구성을 유지하면서 계정·이력 화면을 추가한다. 데스크톱 2열 본문·요약은 모바일에서 1열로 바꾼다. 기준 자료가 바뀐 과거 기록은 삭제하지 않고 과거 결과임을 표시한다.

주요 상태는 로딩·저장 실패·입력 부족·세션 만료·로그인 필요·권한 없음·이력 없음·자료 부족·과거 기준이다. **목록 미완성은 “준비 중” 상태**로 표시하고 기존 예시 목록을 대신 제공하지 않는다.

## 4. 카탈로그 정책

주택 유형은 다음 코드를 사용한다.

| 코드 | 의미 | 범위 |
| --- | --- | --- |
| LH_CONSTRUCTION_RENTAL | LH 건설임대 | 지원 |
| LH_RENTAL_BEFORE_SALE | 분양전환형 임대의 임대 거주 기간 | 지원 |
| SOLD_OR_PRIVATE | 분양주택·분양전환 이후 | 범위 밖 |
| OTHER | 기타 유형 | 범위 밖 |
| UNKNOWN | 유형을 모름 | 추가 확인 |

공간·시설물·증상·질문·동의어는 사용자 지시를 받은 M08A에서 실제 M08 원문을 기준으로 작성·검토했다. [실제 목록](../data/catalog/m08a-20261004/README.md)은 12개 공간·35개 시설·45개 증상·54개 질문이며 공간·시설물·증상과 모든 질문에 모름 경로를 둔다. 기존 초안의 예시나 시험 fixture를 복사하지 않는다.

게시 항목에는 안정적인 ID, 쉬운 표현, 공식 명칭, 공간·시설물·증상의 연결, 질문 선택 값·분기·필수 여부·정렬 순서를 부여한다. 질문은 MVP에서 singleChoice이며 조건은 허용 경로의 equals/in 비교다. 안전 확인 문구·선택 값은 검토한 정책으로 제공하고 M08A에서 누수 진행 여부에 따른 후속 질문 분기를 검토했다. 타는 냄새·연기·스파크와 사용자가 보고한 현재 위험만 승인된 상담 중단 값으로 두며 법률·보수 판정과 구분한다.

형식 검증용 합성 데이터는 테스트 전용 네임스페이스로 관리하고 개발 홈·운영 카탈로그·원문 RAG에 게시하지 않는다. 완성 목록이 없으면 공개 카탈로그 생성·상담 시작을 막는다.

## 5. 결과 상태와 우선순위

| 순서 | 상태 | 의미 |
| --- | --- | --- |
| 1 | SAFETY_PRIORITY | 검토된 위험 신호가 있어 일반 보수 상담보다 안전 확인 우선 |
| 2 | OUT_OF_SCOPE | 알려진 주택 유형이 초기 지원 밖 |
| 3 | NEED_MORE_INFO | 필수 선택·응답 또는 적용 조건 확인이 부족 |
| 4 | NEED_CONFIRMATION | 내부 RAG의 적격 정보가 없음·부족·충돌·철회 |
| 5 | GUIDANCE_AVAILABLE | 해당 맥락에 적용 가능한 검토 근거가 있음 |

“모름”은 유효한 답이다. 서버가 상태를 정하며 프론트·모델이 독자적으로 보수 가능 여부를 판정하지 않는다. 위험 신호는 범위 밖 주택보다 우선하지만 연락처나 직접 수리 방법을 제시하지 않는다. SAFETY_PRIORITY·OUT_OF_SCOPE에서는 미응답 설문을 더 작성하라는 후속 질문을 붙이지 않는다. NEED_MORE_INFO에만 중복 없는 입력 확인 질문을 제공한다.

결과는 증상·선택 요약, 상태와 이유, 근거 기반 안내 또는 확인 사항, 조문·별표 출처, 직접 문의 문구, 생성 시각과 담당 기관 확인 문구를 포함한다. 법령 하자판정 자료와 LH 운영 기준은 구분해 표시한다. 법령 자료만으로 LH의 처리 의무·비용 부담을 확정하지 않는다. DB 장애로 저장할 수 없으면 안내 완료로 표시하지 않고 저장 실패로 알린다.

안전·범위·필수 정보의 우선순위를 통과한 경우, 회원이 명시적으로 요청한 조문·별표 설명은 법령 근거만으로 제공할 수 있다. 설명에 필요한 검토 근거가 충분하면 GUIDANCE_AVAILABLE이며 화면에 ‘법령 기준 설명’으로 표시한다. 설문과 LH 보수·교체·비용 문의는 운영 근거가 없으면 NEED_CONFIRMATION과 직접 문의로 안내한다. 법령 설명을 실제 보수 가능·승인 표시로 바꾸지 않는다. 두 목적이 섞이거나 불분명하면 운영 문의 기준을 적용한다.

### 정보가 부족할 때의 고정 문구

> 관련 정보가 부족하여 안내해 드리기 어려워요. 관리사무소 또는 담당 기관에 직접 문의해 주세요. 실제 보수 여부는 담당 기관 확인이 필요해요.

답변·문의 문구·안전 안내에는 연락처·전화번호·이메일을 넣지 않는다. 기관의 명칭과 문의할 내용은 안내할 수 있다. 근거가 부족할 때 외부 검색으로 답을 채우지 않는다.

문의 문구에는 사용자가 확인한 사실만 넣는다. 구체 증상 목록이 완성되기 전에는 실제 증상 예시 문구를 제품 데이터로 제공하지 않는다.

## 6. 챗봇과 이력 경험

회원 챗봇은 내부 RAG를 먼저 검색하고 관련 조문·조건을 제시한다. 시설물·증상 확인이 필요하면 확인 질문을 제시하고 사용자가 기존 목록에서 다시 선택한다. 사용자 확인 전 맥락을 바꾸지 않는다. 모르는 내용은 모른다고 알리고 직접 문의로 마친다. 연락처를 요청받아도 현 범위에서는 제공하지 않는다.

유효한 상담에서 대화를 다시 열면 질문·답변 한 쌍과 답변 방식·확인 질문·면책 문구를 함께 복원한다. 새로고침 때문에 답변을 재생성하지 않으며 현재 적용 가능 여부는 다시 확인한다.

이전 결과는 생성 당시 입력·답변·출처의 스냅샷이다. 세션이 만료돼도 회원 소유 결과는 조회할 수 있다. 자료 철회·변경·검토 기한 만료가 있으면 과거 기준이라는 표시와 새 상담 버튼을 제공하며 현재 안내로 자동 재해석하지 않는다.

비회원 결과 저장은 현재 상담과 운영 데이터 보존을 위한 것이다. 익명 사용자의 과거 목록을 노출하지 않는다. 현재 세션에서만 결과를 조회할 수 있다는 점을 화면에서 설명한다.

## 7. 보존 설명과 접근성

비회원·회원의 질문 항목·내용은 식별정보를 제거한 별도 기록으로 3~5년 보존하는 계획이며 기본값은 5년이다. 계정 이력도 기본 5년, 익명 원본 결과·대화는 기존 단기안으로 관리한다. 질문 통계는 자료 개선·주요 문의 파악에 활용하되 RAG 정답 지식에 자동 편입하지 않는다. 질문 분석 기록만 지우는 동작과 결과 스냅샷까지 지우는 동작을 구분해 설명한다. 공개 전에 화면의 보존 설명과 실제 정책을 일치시킨다.

결과를 삭제하면 연결된 질문 기록과 재생 응답 본문도 삭제한다. 같은 요청을 다시 보내도 삭제한 결과를 복원하지 않는다. 중복 실행 차단을 위한 본문 없는 요청 기록은 단기 상담 정리까지 남긴다. 삭제 후 새 평가를 시작하는 것은 사용자의 별도 동작이며 자동 재시도하지 않는다.

본문은 18px를 시작점으로 검토하고 주요 버튼은 44×44px 이상을 목표로 한다. 키보드 초점·라디오 그룹·입력 오류 연결·대화 알림·색상 외 상태 설명을 제공한다. 이력 목록·삭제·로그인 오류도 키보드와 스크린리더로 사용할 수 있게 한다.

## 8. 인수 조건

- 비로그인 설문·현재 결과와 회원 챗봇·이력이 화면·서버 권한에서 일치한다.
- 양쪽 사용자의 설문 결과가 저장되고 회원 이력만 계정에 노출된다.
- 완성 목록이 없으면 준비 중이며 기존 예시 증상은 게시되지 않는다.
- 안내·문의 문구에 연락처가 없고 근거 부족은 직접 문의로 연결된다.
- 과거 결과는 생성 당시 근거와 현재 적용 가능 여부를 구분한다.
- 자료 추출은 사용자의 실제 지시 이후 컴퓨터 유즈로 수행한다는 작업 범위를 유지한다.
