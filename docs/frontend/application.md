# 프론트엔드 역할 설계 — TypeScript

상위 문서: [전체 안내](../README.md) · 정책: [기획·UX](../product/service.md) · 계약: [API](../backend/api.md)

챗봇의 이용·초기화 정책은 [챗봇 설계](../product/chat.md)를 따른다.

## 1. 역할과 구성

React + TypeScript + Vite, React Router, TanStack Query, React Hook Form을 사용한다. 기본 5개 상담 화면에 로그인·가입과 이전 결과 화면을 추가한다. 입력 길이·필수 값은 폼 규칙으로 검사하고 서버의 Pydantic 검증을 기준으로 한다. 초기에는 Zod·전역 상태 라이브러리·SSR 서버를 추가하지 않는다. RAG 검색·판단·모델 호출·권한 검증은 서버 책임이다.

```text
frontend/src/
  App.tsx, main.tsx            # Router, QueryClient, 인증 초기화
  pages/                      # Home, Select, Survey, Chat, Result, Login, History
  features/auth/              # 로그인·가입·로그아웃·CSRF
  features/survey/            # 상담·맥락·설문·결과·이력 API, 저장소, 요청 복구
  components/                 # Consultation, Feedback, ResultView, EndConsultation
  api/generated/              # OpenAPI 타입; 직접 수정 금지
  styles.css                  # 기본 스타일·반응형
  features/*/*.test.*          # 시험과 시험 전용 합성 fixture
```

## 2. 인증과 권한

로그인 계정은 서버의 HttpOnly·Secure·SameSite=Lax 쿠키를 사용한다. 브라우저 저장소에 계정 토큰·비밀번호를 저장하지 않는다. 앱 초기화 시 GET /auth/me로 로그인 상태와 CSRF 토큰을 조회한다. 계정 쿠키를 사용하는 변경 요청에 X-CSRF-Token을 보낸다. 자세한 예외·Origin 정책은 [API 설계](../backend/api.md)를 따른다.

로그인 계정 변경·계정 재확인·로그아웃·인증 만료에서 이전 사용자 Query 캐시와 양쪽 상담 복구 정보를 제거하고 늦은 변경 응답을 반영하지 않는다. 회원 챗봇은 본문·대화 복원·상태/근거/과거 표시·응답 유실 복구를 제공한다. [구현 안내](../ai/chat-generation.md)를 따른다. 로컬 HTTP 쿠키 예외는 백엔드 설계를 따른다.

비로그인 설문 세션만 sessionStorage에 세션 ID·익명 Bearer 토큰·만료 시각을 보관한다. 토큰·입력은 URL에 넣지 않는다. 회원 상담은 세션 ID만 보관하고 계정 쿠키로 소유권을 확인한다. 쿠키 인증과 익명 토큰을 같은 것으로 취급하지 않는다.

회원의 surveySessionId와 chatSessionId·요청 복구 키를 별도로 보관하고 Query 키에 계정·용도·세션 ID를 포함한다. `/chat`은 본인 CHAT 세션을 복원하거나 새로 만들며 `/select`·`/survey` 완료 여부를 검사하지 않는다. 설문 결과에서 이동해도 설문 입력을 복사하지 않는다. 계정 전환·로그아웃은 양쪽 캐시를 제거하되 챗봇 초기화는 CHAT 데이터만 정리한다.

설문 세션·질문·현재 결과의 Query 키는 기존 자원 종류·세션 ID·revision/결과 ID 뒤에 계정 ID와 `SURVEY`를 붙인다. 비회원 계정 값은 `null`이며 토큰은 키에 넣지 않는다. 세션 수명과 독립된 회원 이력은 목록/결과 ID·계정 ID·`SURVEY`로 구분한다. 캐시 쓰기는 조회와 같은 전체 키를 사용하고, 세션 종료·결과 삭제·무효화는 기존 자원/세션 접두사로 관련 캐시를 함께 처리한다.

| 경로 | 조건 | 행동 |
| --- | --- | --- |
| `/`, `/login` | 공개 | 소개·로그인·가입 |
| `/select`, `/survey` | 유효한 본인 상담 세션 | 비회원·회원 모두 사용 |
| `/result/:resultId` | 현재 본인 세션 또는 결과 소유 계정 | 현재 결과 조회 |
| `/chat` | 로그인 | 미로그인 시 로그인 안내, 전송 불가 |
| `/history`, `/history/:resultId` | 로그인 | 본인 결과만 목록·상세 조회 |

계정 인증이 만료되면 챗봇·이력 캐시를 제거하고 로그인으로 안내한다. 비회원은 새 익명 설문을 시작할 수 있다. 로그아웃 때 모든 사용자별 Query 캐시·계정 상담 ID를 지운다. 공유 기기에서 이전 계정 결과를 재사용하지 않는다.

## 3. 화면과 카탈로그

| 화면 | 주요 구성 | API |
| --- | --- | --- |
| 홈 | 서비스 설명, 설문, 로그인, 회원 챗봇·이력 | GET /catalog, POST /sessions |
| 선택 | 게시된 주택·공간·시설물·증상, 요약 | PUT .../context |
| 설문 | 서버 singleChoice 질문, 진행·모름·오류 | GET .../questions, PUT .../context, POST .../evaluations |
| 챗봇 | 독립된 회원 대화·입력·채팅 내 확인·근거 펼침·대화 초기화 | POST /sessions(purpose=CHAT), GET/POST .../chat/messages, DELETE /sessions/{id} |
| 현재 결과 | 상태·안내·출처·문의 문구·저장 여부 | GET .../results/{resultId} |
| 로그인·가입 | 이메일·비밀번호, 복귀 경로 | POST /auth/register, /auth/login |
| 이력 | 날짜·요약·상태, 상세·삭제 | GET /me/results, GET/DELETE /me/results/{resultId} |

경로는 /api/v1을 생략했다. 질문·증상은 완성 목록을 게시한 카탈로그에서만 받는다. 기존 예시 항목·임의 증상·임시 ID를 제품 화면에 넣지 않는다. CATALOG_NOT_READY면 준비 중 표시와 홈 복귀를 제공한다. 테스트 합성 목록은 화면 데이터의 대체재가 아니다.

질문은 questionId·label·required·options·interruptValues로 렌더링한다. 위험 확인 선택처럼 interruptValues에 해당하면 맥락 저장 후 서버 평가를 호출한다. 프론트가 표현·보수 기준을 분석해 위험이나 교체 가능성을 판정하지 않는다.

선택 화면은 공간 → 해당 시설물 → 해당 증상 순서로 구성한다. `m08a-20261004-v2`의 넓은 시설물-공간 연결은 UI 탐색용 `features/survey/presentation.ts`에서 공간별 대표 항목으로 좁히고 정렬한다. 현관에는 현관문·신발장·인터폰 등을, 주방에는 싱크대·수전·후드 등을 표시한다. 실제 ID와 서버 기준은 유지하며 시설물 표시명만 공간에 맞춰 풀어 쓴다. 게시 카탈로그·법령 적용 범위·과거 상담은 변경하지 않는다. 다른 카탈로그 버전과 공간 모름은 원래 카탈로그 연결을 사용한다. 기존 저장 선택은 목록에서 빠졌더라도 ‘이전 선택’으로 유지해 수정할 수 있게 한다.

공간을 바꾸면 시설물·증상·답을 모두 초기화하며 시설물을 바꾸면 증상·답을 초기화한다. 같은 값을 다시 선택하면 유지한다. 선택·설문·결과에 3단계 진행 표시를 제공하고, 선택/설문에는 현재 선택 요약과 공간 경로를 표시한다. 좁은 화면에서는 요약을 본문 아래로 배치한다.

## 4. 상태·저장·충돌

| 상태 | 위치 |
| --- | --- |
| 인증·세션·카탈로그·질문·결과·이력·대화 | TanStack Query |
| 아직 저장하지 않은 답·메시지 | 폼·컴포넌트 상태 |
| 계정 CSRF 토큰 | 앱 메모리; 필요 시 /auth/me 재조회 |
| 익명 복구 정보·처리 중 requestId | sessionStorage |

맥락은 context 전체와 expectedRevision으로 저장하고 응답의 정규화된 값으로 갱신한다. 부모 선택이 바뀌면 무효 하위 항목·숨겨진 답을 제거한다. 409 CONTEXT_CONFLICT는 최신 맥락을 조회해 변경을 확인하며 자동 덮어쓰지 않는다.

설문 맥락 변경은 SURVEY 세션에만 적용한다. 챗봇에서 확인한 값은 CHAT 세션에만 저장하고 answers는 비워 둔다. 챗봇의 확인 질문은 채팅 입력으로 답하며 설문 폼·결과를 자동 참조하지 않는다.

설문 평가·채팅마다 UUID requestId를 발급한다. 시간 초과·응답 유실이면 GET .../requests/{requestId} 또는 같은 ID 재전송으로 상태·완료 응답을 확인한다. PROCESSING이면 기다리고 COMPLETED이면 저장된 응답을 표시한다. FAILED는 실패를 설명한 뒤 사용자가 재시도할 때만 새 ID로 실행한다. 새 ID 자동 재전송은 없다. 요청 대기 중 맥락 저장·새 전송을 막는다. 서버 SESSION_BUSY·REQUEST_IN_PROGRESS의 대기 시간을 따른다.

대화 초기화는 확인 후 기존 CHAT 세션 삭제 → 챗봇 캐시·복구 정보·초안 정리 → 새 CHAT 세션 생성 순서다. 전송·복구·초기화 중 버튼을 비활성화한다. 삭제 실패는 기존 대화를 유지하고, 삭제 응답 유실은 기존 세션 조회로 확인한다. 삭제 성공 후 생성 실패는 빈 화면에서 생성만 재시도한다. 새 세션 ID로 전환한 뒤 이전 세션의 늦은 응답을 무시한다. 다른 탭의 종료된 세션도 복원·자동 재전송하지 않는다. 새 대화가 준비되면 입력창으로 초점을 옮기고 완료를 알린다. [상세 초기화 정책](../product/chat.md#3-대화-초기화)을 따른다.

상태 조회가 DELETED이거나 재전송이 410 REQUEST_DELETED이면 삭제된 기록임을 표시하고 해당 결과·재생 응답 캐시와 처리 중 requestId를 제거한다. 자동 재시도·결과 복원을 하지 않는다. 사용자가 새 평가를 명시적으로 시작할 때만 새 ID를 발급한다.

결과 저장은 서버의 평가 완료 트랜잭션에서 자동 수행한다. 저장 실패를 화면에서 성공으로 표시하지 않는다. 회원 생성 결과는 계정 이력, 비회원 결과는 현재 익명 세션에 연결됐다는 표시를 제공한다.

비회원 상담 중 로그인하면 새 회원 상담을 시작한다. 회원 이력은 로그인한 상태에서 생성한 결과만 보여준다. 익명 결과를 계정에 옮기는 버튼·API는 초기 범위에서 제외한다. 기존 익명 결과는 유효한 현재 익명 토큰으로만 조회할 수 있다.

## 5. 결과·이력·대화 표시

결과 상태는 SAFETY_PRIORITY, OUT_OF_SCOPE, NEED_MORE_INFO, NEED_CONFIRMATION, GUIDANCE_AVAILABLE이다. 서버 문구를 승인·비용 확정 표현으로 바꾸지 않는다. LAW_CRITERIA와 LH_OPERATION을 분리하고 Citation.use=RELATED는 참고 자료로 표시한다.

결과 맨 위에 상태별 다음 행동과 서버 안내·추가 확인을 둔다. 문의 문장은 검토된 주택·위치·증상·설문 답변 라벨과 서버 문의 문구로 구성하고 복사 기능과 수동 복사 복구를 제공한다. 자유 입력 설명은 복사 문장에 자동 포함하지 않는다. 입력 상세·출처·저장/보관 설명은 펼침으로 읽을 수 있다. 챗봇 원문은 문단을 나누되 조건·단서·별표 내용은 생략하지 않는다.

법령 설명만을 요청한 대화에서 LAW_CRITERIA에 근거한 GUIDANCE_AVAILABLE·GROUNDED는 ‘법령 기준 설명’으로 표시한다. 법령 인용의 APPLICABLE을 LH 운영 적용으로 표시하지 않는다. 운영 근거가 없는 설문·보수·교체·비용 문의는 NEED_CONFIRMATION과 직접 문의를 유지한다.

정보가 부족하면 안내 불가·직접 문의 문구를 표시한다. 기관 이름은 표시할 수 있지만 연락처·전화번호·이메일·전화 링크를 답변·문의 문구에 넣지 않는다. “대신 웹에서 찾아볼게요” 동작은 없다. 챗봇은 답변 본문·조건·주의사항과 확인 질문을 같은 화면에 표시한다. 근거 펼침에 자료명·조문/별표·서버 제공 excerpt·시행일·검토 정보를 표시하고 출처 원문 HTTPS 링크는 선택적인 확인용으로 둔다. 링크만 반환하거나 링크 방문을 답변 확인의 필수 단계로 두지 않는다.

회원 이력은 만료한 상담 세션과 독립적으로 /me/results에서 조회한다. 과거 결과의 isCurrent=false는 현재 상담·기준과 같지 않다는 의미다. 본문과 생성 당시 출처는 기록으로 보여주고 새 상담을 제공한다. 이력 삭제 성공 시 목록·상세 캐시를 제거한다.

회원 대화는 answerMode와 인용을 표시한다. TEMPLATE·CLARIFY는 정상적인 대체·추가 확인 응답이다. followUpQuestions는 같은 대화 안의 확인 질문으로 표시하고 사용자가 채팅으로 답한다. 확인된 맥락은 CHAT 세션에만 저장하며 모델 답변에서 ID를 추출해 자동 변경하지 않는다. 메시지 목록·재생 답변의 isCurrent=false는 과거 기록으로 표시한다. MVP는 완성 JSON 응답을 사용한다.

GET .../chat/messages는 ChatHistory={items: ChatResponse[], nextCursor}를 반환한다. POST 응답과 같은 질문·답변 쌍 컴포넌트를 사용해 answerMode·status·followUpQuestions·disclaimer를 새로고침 뒤에도 복원한다. requestId로 중복을 제거하고 서버의 쌍 정렬과 cursor를 따른다. 표시 복원 때문에 전송 API를 다시 호출하지 않는다.

## 6. 오류·네트워크

| 코드 | 처리 |
| --- | --- |
| AUTH_REQUIRED·AUTH_EXPIRED | 회원 기능 캐시 제거·로그인 안내 |
| UNAUTHORIZED·SESSION_EXPIRED | 익명 복구 정보 제거·새 설문 |
| CATALOG_NOT_READY | 준비 중; 임의 목록 사용 금지 |
| CATALOG_UPDATED | 최신 완성 카탈로그 조회·선택 재확인 |
| CONTEXT_CONFLICT | 최신 입력과 미저장 입력 비교 |
| SESSION_PURPOSE_MISMATCH | 해당 기능의 별도 세션으로 안내; 설문 입력을 챗봇에 복사하지 않음 |
| SESSION_BUSY·REQUEST_IN_PROGRESS | 대기·동일 requestId 상태 조회 |
| REQUEST_FAILED | 실패 설명; 사용자가 재시도할 때 새 requestId 생성 |
| REQUEST_DELETED | 삭제됨 표시·관련 캐시 제거; 자동 재시도 금지 |
| IDEMPOTENCY_CONFLICT | 같은 ID의 입력이 달라 실행되지 않았음을 설명 |
| INVALID_SELECTION·INVALID_ANSWER·VALIDATION_ERROR | 필드 오류 |
| NOT_FOUND | 자원 없음 또는 소유권 없음 안내 |
| RATE_LIMITED | 입력 유지·Retry-After 후 시도 |
| SERVICE_UNAVAILABLE | 저장 실패 설명·수동 재시도 |

증상 보충 설명은 최대 1,000자, 회원 채팅은 최대 2,000자다. 서버가 같은 제한을 적용한다. 사용자 응답은 no-store로 처리하고 공유·오프라인 캐시를 쓰지 않는다. 채팅 서버 예산 25초·클라이언트 35초, 설문 평가 서버 10초·클라이언트 15초를 초깃값으로 한다.

## 7. 접근성·보안과 인수 조건

공통 메뉴는 홈·챗봇·이전 결과·로그인/로그아웃을 표시하며 현재 경로는 진한 배경과 굵은 글씨로 구분한다. 850px 이하에서는 메뉴를 본문 위 한 줄에 배치해 항상 노출한다. 홈의 설문·챗봇 진입은 PC에서 두 열, 좁은 화면에서 한 열로 배치하며 회원 이용 조건을 표시한다.

PC의 일반 버튼과 입력창은 최소 높이 52px, 메뉴는 48px, 선택형 답변의 라벨은 56px로 제공한다. 600px 이하에서는 본문 16px을 유지하면서 제목은 26~28px, 메뉴 글자는 14px로 줄이고 버튼·입력창·선택 라벨의 최소 높이는 44px로 맞춘다. 브랜드와 메뉴를 포함한 상단 영역은 기본 글꼴에서 112px 이내로 배치한다. 모바일의 주요 행동 버튼은 본문 너비에 맞추며 홈의 설문·챗봇 진입 버튼은 320/360×800px 기본 화면에 모두 노출한다.

주요 행동은 진한 녹색, 보조 행동은 테두리, 삭제·초기화·종료 확인은 경고색으로 구분하고 각 동작의 문구를 함께 표시한다. 모바일의 현재 메뉴는 옅은 배경과 밑줄로 표시한다. 선택한 답변은 라디오·배경·테두리로, 키보드 초점은 외곽선으로 표시한다. 홈은 이용자와 함께 살펴보는 부드러운 문장으로 안내하며, 필요한 설명을 보태되 모바일의 두 진입 버튼 노출을 유지한다. 기록 보관·삭제·외부 전송의 상세 조건은 항목별 펼침 안내에 유지한다.

라디오 질문은 fieldset/legend, 오류는 aria-describedby, 대화 갱신은 aria-live를 사용한다. 360px·확대·키보드·스크린리더에서 로그인·이력·삭제까지 검증한다. 사용자·AI 텍스트는 HTML로 실행하지 않는다. 토큰·원문 입력·대화·비밀번호를 콘솔·분석 이벤트에 남기지 않는다. 출처는 검토된 HTTPS 링크만 표시한다.

- 비회원이 챗봇·이력 경로로 직접 접근해도 사용·조회가 차단된다.
- 설문 없이 챗봇을 시작하고 추가 확인·답변·근거 확인을 사이트 안에서 마칠 수 있다.
- 챗봇 초기화의 취소·성공·실패·늦은 응답·새로고침과 설문 상태 보존을 검증한다.
- 회원 결과는 세션 만료 뒤에도 본인 계정 이력에서 조회된다.
- 익명 결과 저장과 로그인 후 새 회원 상담이 구분되며 과거 익명 결과는 자동 연결되지 않는다.
- 목록 미완성 상태에서 기존 예시 증상이 노출되지 않는다.
- 재시도에서 결과·질문 통계·메시지가 중복되지 않는다.
- 연락처 없는 직접 문의 정책이 결과·채팅·문의 문구에 일치한다.
