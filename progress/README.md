# MVP 개발 진행 안내

작성: 2026-10-03 · 현재 상태: M01~M07 코드/시험 완료 · M08 추출 지시 대기

기준: [전체 설계](../docs/README.md) · 작업 상세: [순서별 MVP 체크리스트](01-mvp-tasks.md)

현재 공통 계약·Docker 실행 환경·12개 DB 테이블·회원 인증·목록 검증/게시·상담/설문/결과/이력/삭제 API와 프론트 화면을 구현했다. 실제 PostgreSQL + pgvector 백엔드 121건, 프론트 33건과 타입/린트/빌드를 검증했다. 실행 명령과 범위는 [로컬 개발 안내](../docs/10-local-development.md)에 기록했다. 실제 목록·정리 원문·OpenAI 연동·운영 배포는 후속 단계다.

계획 점검의 삭제 후 재실행 차단은 M06 API·DB와 M07 화면에서 구현·검증했다. 실제 근거 판단·ChatHistory·백업 복원 후 삭제 재적용은 M09~M11의 작업이다. 범위는 [후속 반영 표](../docs/09-development-standards.md#5-계획-정합성-개정과-후속-반영)를 따른다.

## 1. MVP 완료 범위

완성된 목록으로 비회원/회원 설문과 결과 저장을 제공하고, 회원은 본인 이력과 내부 RAG를 우선 참조하는 챗봇을 이용할 수 있어야 한다. 안내 정보가 부족하면 연락처 없는 직접 문의로 안내한다. 명시적 삭제·3~5년 보존·Docker 배포·백업 복원까지 검증한다.

현재 구성은 TypeScript·React, FastAPI, 단일 PostgreSQL + pgvector, Docker Compose web·api·db, API 1개 워커다. DB 분리·Redis·큐·상시 워커·근사 검색·익명 결과 계정 이전은 [후속 검토 기준](../docs/07-architecture-decisions.md)을 따른다.

## 2. 개발 순서와 상태

## 3. 외부 입력과 진행 제한

| 필요한 입력 | 필요한 단계 | 현재 확인 상태 | 대기 중 할 수 있는 작업 |
| --- | --- | --- | --- |
| M08 이후 작성할 완성 증상·시설물·질문 목록 | M08A 및 M09 | M08 원문 정리 후 작성 | 카탈로그 검증기·준비 중 화면·시험 전용 fixture 기반 코드/자동 시험 |
| 사용자의 실제 원문 추출 지시 | M08 | 미지시 | 앱·DB·권한·자료 반입 검증기 준비; 원문 수집은 하지 않음 |
| 전체 정리·검토 완료 원문/별표와 manifest | M09 실제 청킹·임베딩·게시 | 미확보 | 반입/검색 코드와 mock 시험; 미완료 실제 자료는 처리하지 않음 |
| 서버 OpenAI 키·사용 모델·사용량 설정 | M09 실제 임베딩·M10 실제 생성 평가 | 미확인 | OpenAI OFF/mock 구현·오류/무근거 흐름 검증 |
| 운영 서버·도메인·비밀/백업 저장 설정 | M12 | 미정 | 로컬 Docker·운영 설정 예시·복원 시험 준비 |

순서는 통합 완료 기준이다. M05~M07의 코드·시험 완료와 M08A의 실제 목록 검증을 구분한다. 실제 자료가 완료 기준에 포함된 M08·M08A·M09는 자료 검증을 생략한 채 완료로 표시하지 않는다. M08은 실제 추출 지시가 있으면 착수할 수 있다. M09의 실제 청킹·임베딩은 M08의 전체 정리 검토 완료 뒤에만 실행한다.

시험 fixture는 테스트 전용이며 개발 공개 카탈로그·운영 증상 목록·실제 RAG 지식으로 게시하지 않는다. 법령만 확보한 경우 LH 운영 결론을 임의로 만들어 자료 부족을 채우지 않는다.

## 4. 착수할 작업과 문서 사용

사용자 요청에 따라 완성 목록 작성·검토·실제 게시 검증은 **M08 이후 M08A**로 이동했다. M06 API와 M07 화면의 코드/시험을 마쳤다. 공개 DB는 빈 목록이며 전용 시험 fixture는 자동 시험에서만 사용했다. 다음 단계는 사용자 지시 후 M08 원문 정리다. 실제 목록 작성·게시와 통합 검증은 M08A, 청킹·임베딩은 M09에서 수행한다.

진행 상태와 실행 증거는 progress/에서 관리하고 기능 정책·API·DB·RAG·운영 규칙은 docs/ 설계를 기준으로 한다. 세부 설계가 바뀌면 해당 설계와 영향을 받는 작업을 함께 갱신한다. 구조 확장은 [측정 기준](../docs/08-scaling-roadmap.md)에 따라 결정한다.
