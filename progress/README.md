# 진행 문서 안내

**현재 상태와 다음 작업은 [작업판](current-status.md) 한 곳에서 확인하고 수정한다.** 과거 실행 결과는 [증거 색인](records/README.md)에서 필요한 기록만 찾아 읽는다. 설계·계약·운영 절차는 책임별로 나눈 [docs/](../docs/README.md)가 기준이다. 설계에는 최종 규칙만 남기고 이전안·변경 이유·구현과의 모순 점검 결과는 `records/`에 둔다.

## 수정할 곳

| 변경 내용 | 직접 수정할 파일 |
| --- | --- |
| 요구·설계만 변경 | 해당 설계 문서, 작업판의 관련 작업 |
| 구현·검증·배포 또는 정정 결과 발생 | 새 `records/*.md` 기록, 판단이 바뀐 작업판 행 |
| 과거 결과 조회 | 수정 없이 기록 읽기 |

색인은 기록의 제목·ID·기준일·환경·관계에서 **자동 생성**한다. `records/README.md`를 직접 편집하거나 별도 등록하지 않는다. 작업 상태·완료 조건도 별도 작업 문서에 복사하지 않는다. 완료된 단계의 세부 체크리스트는 R001에 보존되어 있으므로 평상시 읽거나 갱신할 필요가 없다.

작업판은 미완료 작업 중심으로 유지한다. 끝난 작업은 ID·조건·결과를 증거 기록에 남기고, 다른 현재 작업이 선행 조건으로 참조하지 않을 때 작업판에서 제거한다. 단계별 완료 요약과 증거 링크만 남겨 일상적으로 읽는 문서가 이력만큼 늘어나지 않게 한다.

```text
progress/
  current-status.md       유일한 현재 작업판: 상태·환경·입력·남은 작업
  records/*.md            당시 증거 원본: 결과·수치·실패·한계
  records/README.md       자동 생성 색인 — 직접 수정 금지
  templates/record.md     새 증거 작성 양식
  README.md              이 사용 안내 — 작업마다 갱신하지 않음
```

## 변경 한 번의 절차

1. 실제 수행한 일이 있으면 [양식](templates/record.md)으로 `records/`에 새 기록을 작성한다. 색인의 마지막 ID 다음 번호를 사용하고 재사용·재번호 부여하지 않는다. 파일 이름이나 순서는 현재 상태를 결정하지 않는다.
2. 판단이 바뀐 경우에만 [작업판](current-status.md)의 해당 상태·환경·입력·작업을 수정한다. 완료 작업에는 날짜와 증거 링크를 남긴다. 문서 정리만 했다면 서비스 관측일·배포 상태를 바꾸지 않는다.
3. 아래 한 명령으로 색인을 생성하고 참조를 검사한다. 생성 결과도 함께 변경한다. 검사기 코드를 바꾼 경우 회귀 시험을 추가 실행한다.

```powershell
python scripts/check_progress.py --write
# 검사기 변경 시
python -m unittest discover -s scripts/tests -p "test_check_progress.py"
```

CI는 `python scripts/check_progress.py`로 읽기 전용 검사한다. 색인 생성 누락·직접 편집, 최상위의 이전 구조 파일 재생성, 메타데이터 누락/중복, 잘못된 기록 ID 링크, 알 수 없는 작업/입력, 순환 선행 조건, 증거 없는 완료를 실패 처리한다. 별도 설치나 새 데이터 형식 없이 Python 표준 라이브러리만 사용한다.

## 해석 규칙

- 기록은 당시 관측이다. 개발 `8080`, 격리 시험, HTTPS preview `18880`, 실제 운영을 구분한다. 최신 파일 하나가 다른 환경이나 모든 과거 평가를 대체하지 않는다.
- 시험 수치는 기록에 한 번만 적는다. 전체 회귀·부분 검사·mock·실제 제공자 평가를 구별하고 건수를 더하지 않는다.
- 과거 본문·해시·관측 수치는 보존한다. 정정은 새 기록에 대상·이유·영향을 남긴다. 새 기록을 추가하려고 과거 기록에 후속 링크를 일일이 붙일 필요는 없다. 새 기록의 관계가 색인에 나타난다.
- 현재 작업판의 근거가 충돌하거나 없으면 미확인으로 남긴다. 자동 검사는 문장의 사실성·외부 URL·실시간 서비스 상태를 판정하지 않는다.
- `data/private/`, `artifacts/`는 선택적인 로컬 증거다. 저장소에 남는 기록에 결과·범위·한계를 적고 비밀 값은 넣지 않는다.
- 모든 참조는 현재 작업판 또는 `records/`의 정식 경로로 직접 연결한다. `progress/` 최상위에는 이 안내와 `current-status.md`만 둔다. 번호가 붙은 기록은 `records/`에만 작성하며 이전 경로용 파일이나 리다이렉트는 만들지 않는다.
