# MVP 개발 작업 체크리스트

작성: 2026-10-03 · 진행표: [MVP 개발 진행 안내](README.md) · 기준: [전체 설계](../docs/README.md)

M01부터 M12 순으로 통합한다. 외부 자료가 필요한 단계의 실제 처리는 선행 조건을 충족한 후 진행한다. 자료 대기 중 독립적인 코드·mock 시험을 선행할 수 있으며 그 경우 완료 기준의 실데이터 검증은 남겨 둔다. M01~M04는 완료했다. M05 코드·시험을 진행하며 완성 목록·자료 추출은 후속 입력을 기다린다. 단계별 검증 결과를 완료 기록에 남긴다.

- [x] API DTO·오류 코드·catalogVersion·knowledgeReleaseId·revision·requestId의 명칭과 검증 규칙을 개발 기준으로 고정한다.
- [x] 완성 목록을 받을 JSON 형식과 질문·답·분기·자료 범위의 검토 항목을 준비한다.
- [x] 개발·시험·운영 설정을 구분하고 DATABASE_URL·OpenAI 설정·시간·보존 기본값을 예시 설정에 정리한다.

**완료 기준:** 다음 단계에서 프로젝트를 생성할 수 있는 계약·설정 기준이 있고, 완성 목록·추출 지시·운영 설정의 대기 항목이 구분돼 있다.

**완료 기록:** 2026-10-03. 공통 enum·DTO·설정 검증·카탈로그 JSON Schema·시험 전용 fixture·고정 Python 의존성을 구현했다. Ruff 통과, 계약/범위/설정/UTC 검증 8건 통과. 기준은 [개발 기준](../docs/09-development-standards.md)이다.

## M03. 단일 DB와 API 공통 기반

담당 역할: 백엔드, DB · 선행 조건: M02

기준 문서: [DB 설계](../docs/04-database.md), [API 설계](../docs/03-backend.md)

- [x] SQLAlchemy AsyncSession·Psycopg 연결과 Alembic 이력 하나를 구성한다.
- [x] DB 설계의 12개 테이블·FK·UNIQUE·CHECK·필수 인덱스를 migration으로 구현한다. 빈 지식 테이블도 생성하되 원문·벡터는 아직 넣지 않는다.
- [x] 단기 상담 삭제 시 회원 결과·정제 질문이 SET NULL로 남고 단기 요청·대화만 정리되는 관계를 구현한다.
- [x] camelCase 응답·UTC 시간·입력 검증·공통 오류·traceId·사용자 응답 no-store를 구현한다.
- [x] live·ready와 catalogReady·ragReady를 구분한다. 카탈로그가 없으면 상담만 차단하고, DB 장애는 저장·이력 조회를 503으로 처리한다.
- [x] 상담별 메모리 잠금·요청 상태 저장의 공통 코드를 준비하고, OpenAPI로 프론트 타입을 생성하는 절차를 연결한다.
- [x] 실제 PostgreSQL + pgvector에서 migration·관계·공통 오류를 검증한다.

**완료 기준:** 빈 DB에서 migration이 성공하고 DB 제약·삭제 경계·공통 API 응답이 확인된다. API가 1개 워커로 동작한다.

**완료 기록:** 2026-10-03. 단일 AsyncSession 연결·12개 테이블·최초 Alembic migration·삭제 경계·공통 오류/UTC/traceId/no-store·실제 catalog/ready 조회·상담 잠금·요청 상태 저장·OpenAPI 타입 생성을 구현했다. 실제 PostgreSQL + pgvector 시험 19건을 포함해 백엔드 41건, 프론트 2건과 타입/린트/빌드가 통과했다. 빈 시험 DB에서 upgrade/downgrade/반복 upgrade·모델 일치, 단일 프로세스 시작 복구·DB 중단/복구·실제 프록시 응답을 검증했다. 공개 카탈로그·원문·벡터는 비어 있으며 OpenAI 호출은 없다. [실행·검증 안내](../docs/10-local-development.md).

## M04. 회원 인증과 접근 권한

담당 역할: 백엔드, 프론트 · 선행 조건: M03

기준 문서: [API 설계](../docs/03-backend.md), [프론트 설계](../docs/02-frontend.md)

- [x] 가입·로그인·현재 계정 조회·로그아웃 API와 최소 계정 입력 검증을 구현한다.
- [x] Argon2id 비밀번호 해시·계정 토큰 해시·24시간 인증·HttpOnly/Secure/SameSite 쿠키를 적용한다.
- [x] 허용 Origin·Content-Type·쿠키 변경 요청의 CSRF 검증과 로그인/가입 시도 제한을 구현한다.
- [x] 익명 Bearer와 계정 쿠키의 권한 검증을 분리하고 세션·결과·대화의 소유권 검사 함수를 만든다.
- [x] 회원 전용 챗봇·이력 경로를 서버와 프론트에서 제한하고, 타인의 자원은 본문 없이 404로 응답한다.
- [x] 프론트 인증 초기화·로그아웃 캐시 제거를 연결하고 비밀번호·계정 토큰을 브라우저 저장소·로그에 남기지 않는다.

**완료 기준:** 쿠키·CSRF·소유권·만료·로그아웃의 핵심 검증이 통과한다. 비회원에게 회원 기능이 허용되지 않는다.

**완료 기록:** 2026-10-03. 가입/로그인/me/로그아웃·Argon2id·해시 저장·운영/개발 쿠키·Origin/JSON/CSRF·시도 제한·계정/익명 권한·소유권·회원 경로 차단·프론트 계정 초기화/캐시 제거를 구현했다. 실제 PostgreSQL 시험 27건을 포함한 백엔드 54건, 프론트 8건과 타입/린트/빌드를 통과했다. 챗봇/이력의 업무 기능은 M06/M10에서 연결한다. [실행 안내](../docs/10-local-development.md).

- [ ] singleChoice 질문·equals/in 분기와 검토된 위험 확인 정책을 구현한다. 확인되지 않은 보수 조건을 임의로 만들지 않는다.

## M06. 상담·설문 결과·회원 이력 API

담당 역할: 백엔드, DB · 선행 조건: M03·M04·M05; 코드/자동 시험은 M05 자료 대기 중 선행 가능

기준 문서: [API 설계](../docs/03-backend.md), [DB 설계](../docs/04-database.md)

- [ ] 회원·익명 상담 생성·조회·24시간 만료·익명 토큰 해시 저장을 구현한다.
- [ ] 맥락 전체 저장·expectedRevision·동적 질문 조회와 입력 충돌/잘못된 선택 처리를 구현한다.
- [ ] 위험 → 지원 범위 → 필수 입력 → 적격 근거 → 안내의 공통 결정 서비스를 구현한다. 이 단계의 미게시 지식은 안내 불가·직접 문의로 처리한다. 운영 근거가 없는 설문은 법령이 있어도 NEED_CONFIRMATION을 유지한다.
- [ ] 설문 평가·현재 결과 조회·현재 유효성(isCurrent) 계산과 생성 당시 입력·출처 스냅샷을 구현한다.
- [ ] 결과·정제 질문·요청 완료를 한 트랜잭션에 저장한다. 회원 결과는 계정 이력, 비회원 결과는 현재 상담에 연결한다.
- [ ] requestId·입력 해시·완료 응답 재생·PROCESSING/FAILED·충돌·명시적 새 ID 재시도를 구현한다. 같은 상담 변경은 잠금으로 제어한다.
- [ ] 회원 이력 목록/상세·결과 삭제·질문 기록 삭제·상담 종료·익명 eraseRecords를 구현하고 삭제 범위를 구분한다.
- [ ] 결과 삭제와 연결 질문/응답 본문 삭제·요청 DELETED 전환·삭제 로그를 한 트랜잭션으로 구현한다. DELETED·REQUEST_DELETED·RequestState와 요청 저장소를 갱신하고 새 migration으로 DB 제약을 확장한다. OpenAPI·생성 타입·MIGRATION_HEAD도 함께 갱신한다.
- [ ] 삭제된 요청 조회는 DELETED·본문 null, 동일 ID 재전송은 410이며 결과·질문 재생성과 늦은 완료가 차단되는지 검증한다. 질문만 삭제한 경우에도 재생이 질문을 복원하지 않도록 한다.
- [ ] 재시작의 중단 요청 정리·취소 후 늦은 완료 차단·DB 저장 실패를 검증한다. 현재 RAG의 연결점은 준비하되 실제 자료 검색은 M09에서 연결한다.

**완료 기준:** 실제 목록으로 회원·비회원 설문 결과가 저장되고, 회원 이력은 상담 만료 후에도 본인에게만 조회된다. 중복·충돌·명시적 삭제가 검증된다.

**완료 기록:** 아직 없음. 완료 시 산출물·검증 결과·날짜를 기록한다.

## M07. 프론트 기본 이용 흐름

담당 역할: 프론트, 기획·UX · 선행 조건: M04·M05·M06; 화면 구조/자동 시험은 목록 대기 중 선행 가능

기준 문서: [프론트 설계](../docs/02-frontend.md), [기획·UX 설계](../docs/01-product-ux.md)

- [ ] Router·QueryClient·공통 필드/오류/상태/근거 컴포넌트와 모바일 레이아웃을 구성한다.
- [ ] 홈·주택/증상 선택·설문·현재 결과·로그인/가입·회원 이력 목록/상세를 API에 연결한다.
- [ ] 미완성 목록의 준비 중, 입력 부족·저장 실패·세션 만료·로그인 필요·이력 없음 상태를 구현한다.
- [ ] 익명 세션 정보만 sessionStorage에 보관하고 로그인 중 익명 상담을 회원에게 이전하지 않는다. 로그인 후 새 회원 상담을 시작한다.
- [ ] 양쪽 결과 저장 상태·생성 시각·과거 결과 표시·연락처 없는 직접 문의 문구를 제공한다.
- [ ] requestId 기반 응답 복구·중복 클릭 방지·revision 충돌 확인·수동 재시도를 연결한다.
- [ ] DELETED·REQUEST_DELETED를 삭제됨 표시·캐시 제거로 처리하고 새 ID 자동 재시도를 막는다. 새 평가는 사용자 명시적 동작으로만 시작한다.
- [ ] 회원 기록 삭제·새 상담·로그아웃 캐시 제거와 키보드/라디오/오류 접근성을 검증한다. 회원 챗봇 본문은 M10에서 연결한다.

**완료 기준:** 완성 목록으로 홈부터 설문·결과까지 사용할 수 있고, 로그인·회원 이력·삭제·모바일/키보드 흐름이 확인된다.

**완료 기록:** 아직 없음. 완료 시 산출물·검증 결과·날짜를 기록한다.

## M08. 사용자 지시 후 원문 전체 정리

담당 역할: AI·RAG, 자료 검토, 기획·UX · 선행 조건: M01 및 사용자의 실제 추출 지시; 지시가 있으면 M02~M07 개발과 독립적으로 착수 가능

기준 문서: [AI·RAG 설계](../docs/05-ai-rag.md)

- [ ] 사용자가 실제 추출을 지시한 뒤 컴퓨터 유즈 스킬을 확인하고 지정 페이지·별표를 직접 확인한다. 이 작업 목록 작성은 추출 지시가 아니다.
- [ ] 제6조의2·제2장 제7~45조의 본문·항·호·단서·예외와 별표 2의 실제 표·조건·단위·각주를 확보한다.
- [ ] 출처 URL·버전·확보 시각·시행일·원문 위치·내용 해시를 기록하고 확인할 수 없는 값은 그대로 표시한다.
- [ ] 원문과 정리본을 구분하며 생략된 항목을 포함한 전체 문장을 정리한다. '별표 2와 같다'는 참조만 남기지 않는다.
- [ ] 조문별 coverage·별표 연결·누락·검토자·검토일을 검토표/manifest로 기록한다. 누락·접근 실패가 있으면 COMPLETE_VERIFIED로 처리하지 않는다.
- [ ] 법령 참고와 LH 운영 근거를 구분한다. 운영 안내에 필요한 LH 자료가 없다면 법령만으로 보수 의무·비용·교체 결론을 만들지 않는다.
- [ ] 전체 범위 정리와 검토가 완료되면 COMPLETE_VERIFIED와 파일 해시를 기록하고 접근 제한된 파일로 보관한다. 이 단계에서는 청킹·임베딩을 실행하지 않는다.

**완료 기준:** 대상 전체 문장·실제 별표·생략 항목의 완전성 검토가 끝나고 manifest와 원문 위치를 추적할 수 있다.

**완료 기록:** 아직 없음. 완료 시 산출물·검증 결과·날짜를 기록한다.

## M09. 조 단위 청킹·임베딩·내부 검색

담당 역할: AI·RAG, 백엔드, DB · 선행 조건: M03·M05·M08 완료 및 서버 OpenAI 임베딩 설정

기준 문서: [AI·RAG 설계](../docs/05-ai-rag.md), [DB 설계](../docs/04-database.md)

- [ ] 반입 명령이 COMPLETE_VERIFIED·대상 범위·파일 해시를 검사하고 미완료 자료의 청킹을 차단하도록 구현한다.
- [ ] 한 조의 전체 문장을 기본 한 청크로 만들고 실제 별표 청크·relatedChunkIds·상위 조건·예외를 연결한다.
- [ ] 검토 완료 원문·청크·승인 안내 템플릿을 BUILDING 지식 묶음에 반입하고 본문/임베딩 해시·모델·차원을 저장한다.
- [ ] OpenAI Embeddings를 연결해 문서·질문에 동일 모델/차원을 사용한다. 서버 키·배치 사용량을 제한하고 질문 벡터는 요청 메모리에만 둔다.
- [ ] pgvector 정확 검색에 게시 상태·승인·검토 기한·주택 범위 필터를 적용하고 후보 최대 20개·근거 최대 5개 묶음을 구성한다.
- [ ] 실제 목록·검토 원문을 바탕으로 평가셋을 만들고 검색·별표·충돌·철회·운영 적용 조건을 검증한다.
- [ ] 법령만 있는 경우의 명시적 조문 설명과 LH 운영 문의를 분리해 F10a~F10c 평가셋을 만든다. 법령 APPLICABLE이 운영 적용을 뜻하지 않도록 근거 용도·템플릿을 검증한다.
- [ ] 검증이 통과한 묶음만 PUBLISHED로 변경한다. 실패한 BUILDING은 명시적으로 재실행하고 게시본은 덮어쓰지 않는다.
- [ ] M06 설문 평가에 실제 검색과 승인 템플릿을 연결한다. 적용 근거가 없으면 직접 문의 결과를 유지한다.

**완료 기준:** 완료 검토 이후에만 청크·벡터가 생성되고, 세션 고정 지식의 적격 근거만 검색된다. 실제 평가 결과와 게시 기록이 있다.

**완료 기록:** 아직 없음. 완료 시 산출물·검증 결과·날짜를 기록한다.

## M10. 회원 챗봇과 OpenAI 답변 검증

담당 역할: 백엔드, AI·RAG, 프론트 · 선행 조건: M04·M06·M07·M09 및 생성 모델/사용량 설정

기준 문서: [API 설계](../docs/03-backend.md), [AI·RAG 설계](../docs/05-ai-rag.md), [프론트 설계](../docs/02-frontend.md)

- [ ] 회원 전용 대화 조회·전송·ChatResponse·ChatHistory와 챗봇 화면을 구현한다. GET은 저장된 완료 응답의 질문·답변 쌍과 answerMode·status·followUpQuestions·disclaimer를 반환한다. DTO·OpenAPI·생성 프론트 타입을 함께 갱신한다.
- [ ] 새로고침·페이지 조회에서 같은 표시 정보를 복원하고 isCurrent를 재계산한다. 조회 때문에 생성 호출·중복 표시가 발생하지 않는지 F27로 검증한다.
- [ ] 내부 RAG 검색·적격 확인을 생성보다 먼저 실행하고, 근거가 없으면 OpenAI 생성 호출 없이 TEMPLATE/CLARIFY로 반환한다.
- [ ] 생성 전 현재 질문의 목적을 판별한다. 명시적 법령 설명은 적격 법령으로 GUIDANCE_AVAILABLE·GROUNDED를 허용하고, 운영 근거 없는 운영·혼합·불명확 문의는 NEED_CONFIRMATION·TEMPLATE로 처리한다. 공통 안전·범위·필수 정보 우선순위를 유지한다.
- [ ] Responses API·tools=[]·store=false·Structured Outputs·SDK 자동 재시도 OFF·최근 문맥/출력 한도를 적용한다.
- [ ] 주장·수치·조건·인용을 원문/승인 템플릿과 검증하고 URL·날짜·자료 제목은 DB 값으로 조립한다.
- [ ] 외부 검색·사용자 URL 조회·MCP·모델 사전 지식 보충을 막고 답변·안전·문의 문구의 연락처·전화번호·이메일을 차단한다.
- [ ] 25초 전체 deadline·모델 오류·잘못된 출력·가짜 인용의 대체 응답을 구현한다. DB 실패는 503으로 처리한다.
- [ ] 동일 requestId 재생·단일 상담 잠금·사용량 제한·최종 근거 철회 검사를 설문과 같은 처리 규칙으로 연결한다.
- [ ] 대화·정제 질문·요청 완료를 함께 저장하고 확인 질문·근거/과거 표시·로그아웃·소유권·프롬프트 공격을 검증한다.

**완료 기준:** 회원이 내부 근거에 기반한 챗봇을 사용할 수 있고, 무근거 생성·외부 검색·연락처·타인 조회가 차단된다. 모델/원문 변경 평가 결과가 있다.

**완료 기록:** 아직 없음. 완료 시 산출물·검증 결과·날짜를 기록한다.
