## 변경과 경계

T-M15-08 완료. 챗봇은 설문 없이 시작할 수 있고 자동 공유하지 않는다. 사용자가 ‘이전 설문 불러오기’를 펼치면 본인 결과 목록을 페이지 단위로 읽고, 결과를 고른 뒤 ‘선택한 설문 불러오기’를 눌러 현재 대화에 복사한다. 주택·위치·증상·유효한 설문 답변만 가져오며 자유 입력 추가 설명·과거 안내 결론은 제외한다. 다음 질문의 외부 전송 범위를 실행 전에 설명한다.

`POST /sessions/{id}/chat/survey-context`에 resultId·expectedRevision을 보낸다. 서버는 본인 CHAT/결과·CSRF/Origin·잠금·revision·보관 기한·동일 카탈로그를 검증하고 기존 설문 정책으로 정규화한다. 입력이 바뀌면 revision을 올리며 원래 설문·결과·기존 대화는 수정하지 않는다. 복사 API 자체는 외부 호출을 하지 않는다. 일반 context PUT의 답변 주입 금지는 유지하고 전송/복구/초기화 중 불러오기는 막는다. 수정 충돌은 최신 맥락 확인으로 복구한다.

챗봇에 확인한 선택과 설문 답변 개수를 표시한다. ‘배관에서 물이 새요’ 같은 일상 표현을 기존 pipe/leak으로 연결하고, 이미 확인한 증상은 시설 보충 답변에서도 유지한다. 부정 표현으로 누수를 새로 확정하지 않는다. 빠진 시설 또는 증상만 구체적으로 질문한다. 불러온 위험 답변은 조문 질문에서도 안전 우선이며 선택이 바뀌면 이전 설문 답을 비운다.

검색/생성에는 검토된 선택·질문/답변 라벨만 추가 투영하고 자유 원문은 보내지 않는다. 생성 정책 버전을 올려 이전 정책 답변의 현재성 판정을 분리했다. DTO·OpenAPI·생성 TS 타입·브라우저·단위/DB/계약 회귀와 관련 기획/API/AI/DB/프론트/QA 문서를 함께 갱신했다. 새 DB 필드·migration·의존성은 없다.

## 검증

- 격리 PostgreSQL 백엔드 전체 **250건 통과**. opt-in 이전 빈 CHAT, CSRF·타인/비회원/만료/다른 버전 결과 차단, revision 충돌, 복사 후 후속 질문과 답변 유지, 원본 설문 독립, 위험 답변 우선 회귀를 포함한다.
- 초기 전체 실행은 과거 시험 볼륨의 카탈로그/삭제 로그 때문에 빈 DB 전제가 어긋났고 새 경로의 계약 허용 목록도 누락돼 8건 실패했다. 계약 시험을 갱신하고 기존 개발/시험 볼륨을 삭제하지 않은 채 별도 `repair-guide-test-ux-20261022` 시험 볼륨을 준비해 최종 통과했다. DB 이름은 계속 `repair_guide_test`다.
- 프론트 전체 Vitest **59건 통과**. 선택/실행 전 이력 조회·복사 없음, 명시적 불러오기·CSRF·다음 질문 revision·중복 전송 없음 확인.
- 챗봇 모의 API PC/모바일 E2E **2건 통과**. 실제 불러오기 조작·맥락 표시·기존 초기화 취소/이력 동작 확인.
- Ruff 전체·OpenAPI snapshot·생성 타입 일치·ESLint·TypeScript/Vite build·문서/공백 검사 통과.

## 한계

불러오기 대상은 보관 중인 본인 회원 설문 결과이며 미완료 설문·비회원 기록의 계정 이관은 추가하지 않았다. 복사 후 원본 변경/삭제는 챗봇 복사본에 자동 동기화되지 않으며 대화 초기화로 지운다. 실제 OpenAI 재호출·실물 기기·서비스 재배포는 미실행이다.
