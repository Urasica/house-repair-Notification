## 배포와 보존

제품 소스 기준은 `8b571ce`다. 사용자 요청에 따라 기존 `.env`·`.env.ops`, DB/인증서 볼륨, 검토 카탈로그/지식과 OpenAI 활성 설정을 유지하고 API/web/ops를 다시 빌드했다. web의 TypeScript/Vite 빌드도 통과했다. 기존 web/API 완전 중지 후 관리자 연결로 `alembic upgrade head`를 한 번 실행했으며 schema는 이미 head인 `0006_m13`을 유지했다. 새 API는 기존 제한 DB 계정으로 시작했다.

배포 전에는 기존 ops로 삭제 기록을 내보내고 `backup-20261026T105633Z-adb1dadbbefb4ac6b8c36c264dd79008.fernet`(3,035,640바이트)을 만들었다. 검증 뒤에는 새 ops로 `backup-20261026T110609Z-fcf22d565fc3438682f686773003225b.fernet`(3,041,740바이트)을 만들었다. 두 백업 모두 검토 파일 29개와 두 사본의 해시 일치를 확인했다. 삭제 내보내기 항목은 8개다.

기존 보존 정책에 따라 첫 백업 실행에서 기한 지난 암호화 백업 2개를 정리했고 마지막 실행에서는 0개였다. DB의 만료 상담/결과를 지우는 `cleanup`이나 볼륨 삭제는 실행하지 않았다. 백업의 두 경로는 여전히 같은 PC의 `data/private/operations/backups/`와 `remote/`이며 `remoteVerified=true`는 서버 밖 백업을 뜻하지 않는다. 키·비밀번호·환경 전체 값은 기록하지 않았다.

계정·결과·상담·질문·메시지·지식 청크 6종에 대해 ID로 정렬한 행 JSON의 MD5 집계 지문을 기록했다. 배포 직후 모든 건수/지문이 일치했고 브라우저 검증 후에도 배포 전에 있던 행의 지문이 일치했다. 마지막 검사는 시험 시작 전인 `2026-10-26T10:56:32Z` 이전 생성 행과 전체 지식 청크를 비교했다. 이 범위를 DB의 모든 테이블/복원 훈련으로 확대하지 않는다.

기존 합성 시험 계정으로 로그인해 새 비회원/회원 누수 설문과 CHAT을 하나씩 생성했다. 증가분은 이 가상 검증의 결과 2개·상담 3개·질문 4개·메시지 4개다. 새 계정은 만들지 않았다. 기존 기록과 시험 기록을 최종 삭제하지 않았으며 보존 정책을 유지한다. 안전한 집계/지문 원본은 로컬 전용 `artifacts/deploy-20261026/before.json`, `after-deploy.json`, `after-verification.json`에 있다.

## 실제 브라우저 검증

Computer Use의 Browser Use로 모의 API 없이 배포된 `8080`을 확인했다. PC 1440×900과 모바일 360×800을 사용했으며 마지막에는 로그아웃한 홈으로 돌아가 임시 화면 크기를 해제했다.

| 경로 | 결과 |
| --- | --- |
| 모바일 비회원 설문 | LH/주방/싱크대 마감 → 누수 바로가기 → 기존 배관/누수 선택 정상. 설문 진입 시 scrollY=0, 제목 상단 약 235px, 제목 초점 확인 |
| 필수 무응답 | 결과 생성 대신 첫 누락 질문으로 초점 이동·항목별 안내. UNKNOWN 3개를 정상 답으로 저장하고 결과로 진행 |
| 결과/문의 | ‘지금 할 일’이 앞에 표시되고 주택·위치·증상·답변이 문의 문장에 포함. 복사 성공 안내 확인. 입력 상세/출처/보관 설명은 펼침으로 유지 |
| 로그인/이력 | 비회원 상담의 로그인 전 처리 안내 확인. 기존 시험 계정으로 로그인한 뒤 새로고침 없이 이전 결과가 열림. 새 회원 결과도 목록/상세에서 조회 |
| 일상 표현 질문 | 기존에 허용한 가상 문장 ‘LH 건설임대주택이에요. 주방 싱크대 아래 배관에서 물이 새요.’로 주택/공간/시설/증상을 인식. 같은 내용을 재질문하지 않고 담당 기관 확인 안내와 참고 근거 반환 |
| 선택적 설문 불러오기 | 새 CHAT은 빈 맥락. 목록 열기 → 이번에 만든 회원 결과 선택 → 실행 후 선택 정보·설문 답변 3개 표시. 새로고침 후에도 유지하며 기존 답변은 과거 revision으로 표시 |
| 실제 생성 | 같은 누수 범위의 후속 질문 ‘제10조에서 배관 누수와 관련해 어떤 내용을 확인할 수 있나요?’에 ‘관련 기준 안내 / 근거 확인 답변’(`GROUNDED`) 완료. 원문·별표 2·각주와 출처가 같은 화면에 표시됨 |
| 초기화/삭제 취소 | 대화 초기화 취소 후 기존 대화와 설문 맥락 유지·입력창 초점 복귀. 새 시험 결과의 삭제 확인은 설명이 연결된 취소 버튼에 초점을 주고, 취소 후 ‘이 결과 삭제’로 복귀. 최종 삭제/초기화는 실행하지 않음 |
| 로그아웃 | 챗봇에 다시 접근하면 로그인 게이트가 열리고 이전 회원 대화를 표시하지 않음 |

모바일 설문/챗봇에서 가로 넘침이 없었다. 챗봇 화면의 주요 메뉴·버튼·선택/펼침 조작 영역은 44px 이상이었다. 기존 홈 브랜드 링크는 34px 높이를 유지하므로 모든 링크가 44px라고 판정하지 않는다. 이번에 axe/스크린리더 전체 검사를 다시 실행하지 않았다.

실제 외부 호출은 기존에 승인받은 가상 누수와 같은 범위의 후속 질문만 사용했다. 실제 개인정보는 입력하지 않았고 서비스의 기존 선택/질문·답변 라벨·조문 위치·검토 자료 투영 경계를 유지했다. 생성 한 상황의 성공을 전체 모델 품질 재평가나 LH 운영 기준 확보로 해석하지 않는다.

## 기본 검사와 한계

`scripts/smoke_api.py --url http://localhost:8080 --rag-ready --catalog-version m08a-20261004-v2`에서 web/live/ready/카탈로그/비회원 인증 차단/API 오류 점검이 종료 코드 0으로 통과했다. 재배포한 제품 소스는 변경하지 않았다. 문서 색인/링크와 `git diff --check`를 확인했다.

이번에는 배포·실제 브라우저 과업·기본 API·데이터 보존을 검증했다. 전체 단위/DB/모의 API E2E 회귀는 재실행하지 않았으며 그 범위는 [R027](27-ux08-focus-and-integration.md)의 당시 결과를 따른다. 이번 브라우저 검증은 기존 합성 계정으로 로그인했다. 가입 후 연속 로그인 자체는 재실행하지 않았고 [R026](26-ux07-storage-and-signup.md)의 회귀를 따른다. 실물 모바일·스크린리더·복원 훈련·실제 운영 서버/HTTPS 인수는 미실행이다. 격리 시험/preview·운영 설정을 변경하지 않았고 개발 서비스는 실행 상태로 남겼다.
