# 진행 문서 구조와 참조 체계 개정

> 기록 ID: R011 · 기준일: 2026-10-18 · 환경: 저장소 Markdown·문서 검사·CI 설정
> 관계: R001~R010의 당시 결과는 보존하고 현재 판단·작업·기록의 관리 위치를 분리한다.
> 당시의 증거 기록이다. [최신 상태](../current-status.md)와 [남은 작업](../current-status.md#남은-작업)을 먼저 확인한다.

## 변경 이유와 범위

누적 안내에서 M12 당시 시험 수치가 현재 상태처럼 남고, M13 격리 검증·개발 서비스 재배포·preview/실제 운영 인수가 섞여 해석될 수 있었다. 완료 체크리스트의 과거 계획과 새 작업도 같은 본문에서 계속 늘어났다.

- 최신 상태를 `current-status.md`로 모으고 환경별 기준일·근거·미검증 범위를 명시했다. 시험 건수는 개별 증거로 연결하고 복사하지 않는다.
- 기존 체크리스트는 R001 스냅샷에 보존했다. M01~M07 인라인 완료 기록을 유지하고 M12의 원격/스케줄/경보·실제 복원·스크린리더/확대 인수까지 T-M12-01~08로 모았다. 기존 절 링크도 유지했다.
- 기존 02~10 기록은 `records/`로 옮기고 고정 ID·기준일·환경·후속 관계를 붙였다. 본문의 과거 수치·해시·실패·한계는 소급 수정하지 않았다. 이전 경로는 이동 안내로 남기고 저장소 내 참조는 정식 경로로 바꿨다.
- 색인과 새 기록 양식·갱신 순서를 추가했다. 설계 문서는 구현 상태를 복제하지 않고 최신 상태/해당 시점의 증거를 참조하도록 정리했다.
- [문서 검사](../../scripts/check_progress.py)와 회귀 시험을 추가하고 CI에 연결했다. 로컬 파일/절 링크, 색인 누락·중복 ID/경로, 메타데이터, 현재 상태·작업의 증거 참조를 검사한다. Git 제외 원문/캡처는 선택 로컬 증거로 구별한다.

## 검증과 한계

| 검증 | 결과 |
| --- | --- |
| `python scripts/check_progress.py` | 저장소 Markdown 46개·색인 기록 11개 통과. 선택 로컬 증거 링크 11개는 존재 여부 검사에서 제외 |
| `python -m unittest discover -s scripts/tests -p "test_check_progress.py"` | 6건 통과. 파일/절 누락·빈 절·이전 경로 참조·미색인 기록·중복 ID·메타데이터 불일치·완료 증거/작업 참조 누락 탐지 |
| 새 검사기/시험 정적 검사 | 저장소의 `backend/pyproject.toml` 기준 Ruff 검사·포맷 통과 |
| 기존 추적 기록 본문 대조 | 02~08의 7개 기록을 기존 Git 본문과 대조. 이동한 링크와 추가 메타데이터·공백을 제외한 본문/수치/해시 일치 |

초기 시험의 임시 디렉터리는 Windows 실행 권한 제한으로 실패해 작업 폴더의 `.cache/progress-tests/` 안에서 생성/정리하도록 수정했다. 수동 문서 검토에서 체크리스트 이관 링크의 빈 절 주소를 발견해 각 단계의 실제 절 주소로 수정하고 빈 절 검사도 추가했다. 위 표는 수정 후 재검증 결과다.

이 기록은 문서 구조 개정에 한정하며 실제 서비스 재배포·DB 변경·OpenAI 호출은 수행하지 않았다. 호스팅 CI 실행 성공을 뜻하지 않는다.

자동 검사는 문장의 사실성이나 최신 외부 상태까지 보장하지 않는다. 후속 변경마다 새 증거를 등록하고 최신 상태·작업을 함께 갱신해야 한다. 실제 운영 인수와 자료의 적용 제한은 기존 상태/작업에 남긴다.
