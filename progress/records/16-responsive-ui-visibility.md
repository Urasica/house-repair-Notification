# PC·모바일 메뉴와 버튼 시인성 1차 개선

> 기록 ID: R016 · 기준일: 2026-10-18 · 환경: 로컬 소스·Node 22.23.1·Vite·Vitest/jsdom·Chromium PC/모바일 에뮬레이션·mock HTTP
> 관계: R015 이후 UI 표현을 개선한다. R009/R010의 API·배포 증거는 유지하며 이번 결과를 서비스 재배포 증거로 사용하지 않는다.

## 변경 이유와 대상

M14의 T-M14-01: PC와 모바일 웹에서 메뉴와 버튼을 쉽게 구분하고 누를 수 있도록 개선한다. 완료 조건은 주요 화면의 메뉴·동작 구분, 충분한 클릭 영역, 가로 넘침 없는 반응형 배치와 소스·브라우저 회귀 검증이다. 2026-10-18 소스·모의 API 검증 범위에서 완료했다.

공통 메뉴에 홈을 추가하고 현재 경로 표시·모바일 메뉴 노출·로그인 테두리를 적용했다. 홈에서 설문과 챗봇 진입을 구분하고 좁은 화면에서는 한 열로 배치했다. 버튼·입력·선택 라벨의 크기와 대비, 선택한 답변·진행 단계·키보드 초점을 강화했다. 결과·이력·설문 이동 링크는 버튼으로 표시하고 삭제·초기화·종료 확인은 경고색으로 구분했다. 챗봇의 내 질문과 답변, 확인 동작 사이의 간격도 정리했다.

기존 인증·설문·챗봇·데이터 보존 동작과 작업 시작 전 수정사항을 유지했다. API/DB·게시 카탈로그·모델 설정·의존성은 변경하지 않았다. 최종 표시 기준은 [프론트 접근성 설계](../../docs/frontend/application.md#7-접근성보안과-인수-조건)를 따른다.

브라우저 검증은 개발 Vite의 모의 API로 실행해 실제 계정·DB·OpenAI를 호출하지 않았다. Playwright 설정에 PC와 모바일 프로젝트를 두어 기존 실제 서비스 E2E도 양쪽 화면에서 실행할 수 있게 했다. 기존 실제 서비스 E2E는 이번에 실행하지 않았다.

초기 검증 중 로컬 서버의 sandbox 연결 제한은 sandbox 밖 로컬 Vite/Chromium 실행으로 해결했다. 새 E2E의 오류 설명 인수에서 발견한 nullable 타입은 문자열로 수정한 뒤 최종 빌드가 통과했다. 화면 캡처 검토 후 모바일 홈 간격과 메뉴 열 너비를 조정하고 브라우저 검증을 다시 통과했다.

## 한계와 후속

실제 스마트폰·Safari/Firefox·스크린리더·브라우저 확대의 수동 검증은 수행하지 않았다. 좁은 viewport 검증은 실제 브라우저 확대 검증을 대체하지 않는다. 개발 8080/HTTPS preview/운영 서비스 재배포 및 실제 카탈로그·DB E2E는 수행하지 않았다. 이후 배포 시 실제 데이터의 긴 문구와 기기별 표시를 확인한다. 기존 M12 운영 인수 작업은 유지한다.
