## 구현 결과

- `0006_m13`에서 consultations.purpose 기본값 SURVEY·허용값 CHECK·회원 CHAT 제약을 추가했다. 설문 질문/평가와 채팅 전송의 용도 검사는 소유권 검사 후 수행한다. 기존 공유 상담의 완료 CHAT 기록은 과거 조회만 허용한다.
- 챗봇은 별도 CHAT 세션과 브라우저 저장 키·계정별 Query 캐시를 사용한다. 설문 답·결과를 복사하지 않고 챗봇에서 확인한 명시적 주택 유형과 검토된 카탈로그 표현만 맥락에 반영한다. 조건이 부족하면 채팅으로 묻고 ‘모름’은 추가 추정 없이 확인 필요로 안내한다. 조문 설명은 설문 입력 없이 처리한다.
- 대화 초기화는 확인/취소 → 기존 CHAT 삭제 → 캐시·초안·요청 복구 정보 정리 → 새 CHAT 생성이다. 삭제 실패·다른 요청 처리 중·삭제 응답 유실·새 세션 생성 실패를 구분한다. 로그인·설문·회원 결과·장기 정제 질문·사용량 한도는 유지한다.
- 챗봇 답변을 화면에 직접 표시하고 인용의 excerpt·조건·단서·별표 셀/비고·출처 정보를 사이트 내 펼침으로 제공한다. 원문 링크는 선택적 확인용이다. OpenAPI와 생성 프론트 타입, 실행/부하 검증 스크립트를 함께 갱신했다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| 격리 PostgreSQL + pgvector 기반 전체 백엔드 회귀 | 243건 통과 |
| 마지막 확인 문구 수정 후 챗봇 회귀 | 23건 통과 |
| 프론트 Vitest | 49건 통과 |
| 정적 검사·계약 | Ruff 검사/포맷, TypeScript, ESLint, OpenAPI snapshot·생성 타입 일치 통과 |
| 빌드·DB 변경 | 프론트 빌드, Docker api/web 빌드, `alembic upgrade head`와 `alembic check` 통과 |
| 실제 브라우저 | 360px Chromium 핵심 흐름 2건과 axe WCAG AA 검사 통과 |

DB 시험은 개발 DB와 분리된 `repair-guide-test` 프로젝트의 `repair_guide_test`에서 실행했다. 전체 DB 회귀를 먼저 수행하고 실제 검토 카탈로그를 게시한 뒤 브라우저 시험을 수행한다. 브라우저 시험은 단기 기록과 사용량을 남길 수 있으므로 DB 회귀에 같은 데이터를 섞지 않는다. 최종 챗봇 회귀 전에는 해당 테스트 DB의 `e2e-...@example.com` 합성 계정과 연결 데이터만 정리했다.

실제 브라우저에서는 설문 미작성 회원의 챗봇 진입·전송·새로고침 복원, 이후 설문 작성에도 기존 챗봇 유지, 초기화 취소/성공, 입력창 초점 복원, 초기화 후 새로고침, 설문 ID·결과 이력 유지, 삭제·로그아웃을 확인했다. 화면 캡처는 로컬 `artifacts/m13/`에 있다.

## 적용 범위와 실행

코드 검증 당시에는 기존 개발/운영 DB·실행 이미지를 변경하지 않았다. 이후 사용자 요청으로 기존 로컬 서비스에 재배포했다. [재배포 기록](10-local-redeploy-image-cleanup.md)을 따른다. 다른 환경에 반영 시 기존 API를 중단하고 새 이미지 빌드 → 관리자 연결로 `alembic upgrade head`(0006_m13) → 단일 API/web 재시작 순서를 따른다. 데이터가 있는 DB에 downgrade를 실행하지 않는다. 기존 공유 상담은 SURVEY로 유지하고 그 입력·대화를 새 CHAT으로 복사하지 않는다.

이번 변경에서 실제 OpenAI를 재호출하지 않았다. 검색·생성 계약과 근거 게이트는 고정 벡터와 생성 mock으로 검증했고 브라우저는 OpenAI OFF로 실행했다. 검토 원문/승인 문구 선택 방식은 유지하며 임의 자유서술 이해·의역의 정확도 전반을 검증한 결과로 해석하지 않는다. 운영 배포와 원격 백업/스케줄 인수는 기존 M12 범위다.
