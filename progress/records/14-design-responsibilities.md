> 관계: R011/R012/R013의 단일 작업판·증거 기록 구조를 유지하고 설계 문서의 책임 경계와 최종 기준을 정리한다. R009/R010의 구현·배포 판정은 변경하지 않는다.

## 변경 범위

사용자 요청에 따라 설계 문서 16개를 제품·프론트엔드·백엔드·데이터·AI·품질·운영·아키텍처·개발의 9개 책임 폴더로 옮겼다. `docs/` 최상위에는 README만 남겼으며 이전 번호 파일·리다이렉트는 두지 않았다. 정식 경로와 책임은 [설계 색인](../../docs/README.md)에서 확인한다. 루트 안내·자료 안내·진행 기록의 경로도 함께 갱신했다.

설계 본문에서 단계별 완료 내역·과거 시험 건수·환경 관측·이전안 비교를 제거했다. 과거 실행 결과는 R001~R010에서 확인하고 현재 적용 상태는 작업판에서만 판단한다. 기록의 관측 수치·해시는 소급 변경하지 않았다.

- 설문 작성 후 챗봇으로 넘어가는 옛 흐름은 제거하고 독립 CHAT 이용·초기화·사이트 내 근거 정책을 제품 문서로 통합했다.
- 개발 기준의 개정 이력표를 계약 변경 규칙으로 정리하고 로컬 실행의 과거 검증 절·중복 운영 명령을 제거했다. 운영 배포는 별도 비밀 설정과 삭제 내보내기를 포함한 운영 절차로 연결한다.
- 지식·생성 평가 명령의 특정 실행 ID·해시·개인 체크아웃 경로는 명시적 입력 자리표시자로 바꿨다. 모델·1536차원·임베딩 총량 무제한·요청별 제한은 유지한다.
- 기존 공유 상담의 읽기 호환, 삭제/복원, 근거 검토, 권한·안전·오류 처리와 F01~F34 기준은 최종 설계에 보존했다.

## 코드와 문서의 미해결 모순

아래 두 항목은 **미수정**이다. 사용자의 지시에 따라 차이를 발견한 계약과 구현을 임의로 일치시키지 않았다. 코드가 틀렸다고 단정하거나 구현 완료 판정을 취소한 목록은 아니며, 어느 쪽을 기준으로 삼을지 결정할 대상이다.

### D01. 설문 Query 키의 계정·용도 누락

- 설계: [프론트 인증·권한](../../docs/frontend/application.md#2-인증과-권한)과 [챗봇 데이터 경계](../../docs/product/chat.md#5-계약과-데이터-경계)는 양쪽 Query 키에 계정·용도·세션 ID를 포함하도록 한다.
- 코드: [useSurvey.ts](../../frontend/src/features/survey/useSurvey.ts) 14행은 CHAT 키에 계정·용도를 포함하지만 SURVEY 키는 `['session', reference?.id]`다. [Survey.tsx](../../frontend/src/pages/Survey.tsx) 31행의 질문 키도 `['questions', session.id, session.revision]`이다.
- 영향: 문서에 명시한 캐시 식별 규칙과 구현이 다르다. [state.ts](../../frontend/src/features/auth/state.ts)의 계정 전환·로그아웃 캐시 정리와 세션 ID 구분은 존재하므로, 이 차이만으로 다른 사용자 데이터 노출이 재현됐다고 판단하지 않는다.
- 검토 방향: 현재 캐시 정리 방식을 공식 계약으로 인정할지, 모든 설문 키에 계정·용도를 넣는 계약을 구현할지 결정해야 한다.

### D02. 백엔드 디렉터리 설계와 실제 배치 차이

- 설계: [API 책임·구조](../../docs/backend/api.md#1-책임과-구조)는 `backend/app/rag/`와 `backend/app/integrations/openai/`를 별도 디렉터리로 명시한다.
- 코드: 두 디렉터리는 없다. 검색·생성·임베딩은 [retrieval.py](../../backend/app/services/retrieval.py), [generation.py](../../backend/app/services/generation.py), [embeddings.py](../../backend/app/services/embeddings.py) 등 `services/` 안에 있다.
- 영향: 기능 오류 증거는 아니지만 문서를 보고 구현 위치를 찾거나 새 모듈을 추가할 때 잘못된 구조를 참조할 수 있다.
- 검토 방향: 현재 `services/` 배치를 설계로 채택할지, 설계대로 분리할지 결정해야 한다. 이번에는 도표 수정이나 코드 이동을 하지 않았다.

## 검증과 한계

정적 대조 범위는 세션 용도·맥락/Query 키·초기화·인용 표시, API DTO, 생성 입력/한도, 백엔드 파일 배치다. React Hook Form은 로그인 화면에서 사용하며, CHAT Query 키·근거 시행일/검토일 표시는 코드에서 확인했다. 이 항목들을 미구현으로 보고하지 않는다.

| 검사 | 결과 |
| --- | --- |
| `python scripts/check_progress.py --write` 및 읽기 전용 검사 | Markdown 39개·정식 기록 14개, 파일/절 링크·메타데이터·색인 일치 통과; 선택적 로컬 산출물 링크 11개 제외 |
| 설계 구조·이전 경로 | 책임 폴더 9개·설계 16개·최상위 색인 1개; 문서·진행 기록·자료 안내·루트 안내에 이전 설계 파일명 참조 없음 |
| 문서 외 변경 방지 | 작업 시작 시의 코드·설정 등 196개 파일 SHA-256과 동일; 기존 미커밋 변경도 그대로 유지 |

문서 검사기는 변경하지 않았다. 외부 URL의 유효성·원문 재검토·운영 명령 실행은 이번 검증 범위가 아니다.

서비스 코드·설정·DB·배포 환경을 변경하지 않았다. 앱 회귀·브라우저·실제 OpenAI·운영 배포 검증은 재실행하지 않았으며, 문서 검사 통과는 기능 인수나 위 두 모순의 해소를 의미하지 않는다.
