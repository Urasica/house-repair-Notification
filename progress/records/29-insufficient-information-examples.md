# 정보 부족 안내의 가상 보수 검토 예시

> 기록 ID: R029 · 기준일: 2026-10-28 · 환경: 소스·격리 PostgreSQL/OFF·mock·개발 localhost:8080/실제 게시 자료·OpenAI ON·Chromium PC/모바일
> 관계: R028의 개발 배포에 정보 부족 결과의 예시를 추가한다. R020~R028의 UX 구현·과거 검증 기록과 실제 운영 인수 범위를 대체하지 않는다.
> 당시의 증거 기록이다. [현재 상태](../current-status.md) · [갱신 방법](../README.md)

## 변경과 경계

M16/T-M16-01: 사용자가 설문을 모두 모르겠다고 답하거나 핵심 정보가 부족할 때, 직접 문의만 보여 주는 대신 이해를 돕는 가상 보수 검토 예시를 함께 제시했다. [결과 정책](../../docs/product/service.md#정보가-부족할-때의-고정-문구)·[답변 정책](../../docs/product/chat.md#4-웹사이트-내-답변과-근거-표시)·[API 계약](../../docs/backend/api.md)을 함께 반영했다.

- 설문·채팅 응답에 선택적 `referenceExamples`를 최대 2개 제공한다. 배관 누수는 연결 부위와 손상 부위, 문·창문은 닫힘과 부품 상태를 예로 든다. 그 밖의 증상은 해당 카탈로그의 조건 없는 상세 질문에서 UNKNOWN·위험 중단 값을 제외한 관찰 항목을 사용한다.
- 시설물·증상을 모두 특정하지 못한 경우에만 배관·문의 ‘일반 예시’를 보여준다. 시설물만 알고 증상을 모르면 무관한 예시를 붙이지 않는다. 위험 우선·범위 밖 주택·법령 설명·적용 가능한 근거 안내와 가스/전기 설비/소방/승강기/난간/옹벽에는 예시를 제외한다.
- 실제 처리 이력·수리 승인·비용 판단으로 표현하지 않는다. ‘가상 예시’, 현장 확인과 실제 처리의 차이, 아는 증상만 전달해도 된다는 설명을 같은 영역에 둔다. 직접 문의·추가 확인은 유지한다.
- 예시는 서버의 편집 문구이며 검색·생성 입력·문의 복사문·인용에 추가하지 않는다. 출처 장애 시에도 독립된 편집 예시만 유지한다. LH_OPERATION 미확보·운영 판단 제한은 그대로다.
- 새 응답에 예시를 함께 저장·복원한다. 기존 저장 JSON에는 기본 빈 목록을 적용하고 과거 기록을 재작성하지 않는다. 정책 버전은 `survey-v4-reference-examples`·`chat-v4-reference-examples-extractive`이며 이전 버전은 과거 결과로 표시한다. DB migration·새 의존성은 없다.

## 로컬 반영과 데이터

기존 `.env`·`.env.ops`·삭제 내보내기·DB/인증서 볼륨을 유지해 API/web만 빌드·완전 중지·재생성했다. migration은 실행하지 않았다. 실행 이미지는 최종 API `7091c758cae7`, web `669cac04aed3`이며 자산은 `index-X7-zNM05.js`·`index-Dn4-vSi_.css`다. 브라우저 검증 시 API는 `dad5d0365359`였고 마지막 연락처 필터만 추가 반영했다. 마지막 반영 후 기본 API 검사를 다시 확인했다. 이전 실행 이미지는 각각 `pre-examples-20261028` 태그로 보존했다. 호스트 공개는 `127.0.0.1:8080`뿐이고 기존 카탈로그/지식을 재게시하지 않았다.

삭제 내보내기 8개를 확인하고 배포 전 `backup-20261028T080410Z-f8916245216049a89062a6f1bc295105.fernet`(3,041,740바이트), 검증 후 `backup-20261028T081132Z-bd348e641ce84546ad8f9314a6c40fc4.fernet`(3,045,432바이트)을 만들었다. 각각 검토 파일 29개와 두 사본의 해시 일치, 기한 만료 백업 정리 0개를 확인했다. 자동 승인 검토에서 최초 백업의 `/remote` 목적지 확인을 요구해, 실제 경로가 워크스페이스 내부의 일반 폴더임을 확인한 후 같은 명령이 승인·완료됐다. 두 백업 경로는 같은 PC이며 서버 밖 복제를 뜻하지 않는다.
