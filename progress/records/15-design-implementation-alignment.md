# 설문 캐시 식별과 백엔드 구조 문서 정합성 수정

> 기록 ID: R015 · 기준일: 2026-10-18 · 환경: 로컬 소스·Node 22.23.1·Vitest/jsdom·mock HTTP·문서 검사
> 관계: R014의 D01/D02를 사용자 승인 방향으로 해결한다. R009/R010의 기존 실행·배포 증거는 유지하며 이번 변경의 배포 증거로 사용하지 않는다.
> 당시의 증거 기록이다. [현재 상태와 남은 작업](../current-status.md) · [갱신 방법](../README.md)

## 결과와 범위

| 대상 | 수정 | 판정 |
| --- | --- | --- |
| D01 | 설문 세션·질문·현재 결과 Query 키에 계정 ID·SURVEY 추가. 세션과 독립적인 회원 이력도 계정·용도로 구분 | 코드·프론트 회귀 검증 완료 |
| D02 | API 설계의 디렉터리 도표를 실제 services 배치로 수정. 검색·생성·임베딩 파일의 책임과 main/API/domain/DB/Alembic 위치 명시 | 문서·파일 배치 대조 완료 |

D01의 조회와 쓰기는 같은 전체 키를 사용한다. 새 설문 시작, 선택·답 저장과 충돌 후 재조회, 평가 완료·응답 유실 복구의 결과 캐시까지 함께 변경했다. 기존 자원 종류·세션 ID·revision/결과 ID의 위치는 유지하므로 접두사 무효화·종료·결과 삭제는 관련 캐시를 계속 제거한다. 비회원 계정은 null이며 토큰을 키에 넣지 않는다.

계정 변경·로그아웃 캐시 정리, identityEpoch와 세션 확인을 통한 늦은 응답 차단, CHAT 전용 초기화는 유지한다. 범용 키 생성 계층이나 새 의존성은 추가하지 않았다. D02는 문서만 수정하고 백엔드 파일·import·DB·API 계약을 변경하지 않았다.

최종 기준: [프론트 캐시 정책](../../docs/frontend/application.md#2-인증과-권한), [백엔드 책임·구조](../../docs/backend/api.md#1-책임과-구조).

## 검증

| 검사 | 결과 |
| --- | --- |
| 프론트 전체 회귀 `npm test` | 6개 파일·52건 통과. 비회원/회원 설문 전체 흐름, 계정 전환·로그아웃 후 늦은 응답 차단, 결과 삭제·복구 포함 |
| 결과 캐시 분리 | 현재 결과/회원 이력에서 다른 계정 키 및 계정 없는 기존 키에 유효한 캐시가 있어도 현재 계정의 API 응답을 조회·표시 |
| 챗봇 초기화 | 새 형식의 설문 캐시를 보존하고 이전 CHAT 세션·메시지 캐시만 제거. 검증 추가 후 전체 52건 재통과 |
| 정적 검사·산출물 | TypeScript 검사·ESLint·Vite 빌드 통과 |
| 문서·변경 검사 | Markdown 40개·기록 15개 링크/메타데이터/자동 색인 검사 및 git diff --check 통과 |

최초 시험은 Windows sandbox 임시 경로의 ENOENT로 2개 suite를 불러오지 못했다(나머지 15건 통과). 코드 assertion 실패가 아니었다. PowerShell 실행 프로세스의 TEMP/TMP를 저장소 내 `.cache/node-tmp/d01-d02`로 지정한 뒤 전체 시험이 통과했다. 시스템 설정이나 프로젝트 테스트 설정은 변경하지 않았다.

## 한계

브라우저 실제 서비스 E2E·DB 회귀·OpenAI 호출·서비스 재배포는 수행하지 않았다. 이번 결과는 소스·mock HTTP 화면 회귀와 빌드의 확인이며 현재 실행 중인 개발/preview/운영 서비스에 적용됐다는 뜻이 아니다. R014의 당시 미수정 기록은 보존하고 현재 판정만 작업판에서 갱신한다.
