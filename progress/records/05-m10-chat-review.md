# M10 회원 챗봇 완료 기록

> 기록 ID: R005 · 기준일: 2026-10-05 · 환경: 로컬 회원 챗봇·실제 생성 평가
> 관계: R009가 세션 공유·답변 표시를 개정; 당시 실제 평가 결과는 보존.
> 당시의 증거 기록이다. 본문의 상태·수치·다음 작업은 해당 시점에 한정한다. [최신 상태](../current-status.md)와 [남은 작업](../current-status.md#남은-작업)을 먼저 확인한다.

완료일: 2026-10-05(KST) · 로컬 개발 서비스 반영 · 다음 M11

회원 전용 대화 조회·전송, ChatHistory·ChatResponse, Responses API, 생성 검증, 원자 저장, 중복 복구, 회원 화면을 연결했다. 생성 모델은 사용자 지정 gpt-5.4-mini이며 임베딩은 기존 large·1536차원을 유지한다. 컴퓨터 유즈 없이 코드·DOM 시험·실제 DB/API로 검증했다.

## 구현

- 내부 적격 검색이 생성보다 먼저 실행된다. 명시적 법령 설명에만 검토된 조문 전체를 선택·인용하고 연결 별표의 모든 셀·비고를 표시한다. LH 운영 근거 없는 질문은 직접 문의를 유지한다.
- 모델의 임의 주장·가짜 인용·조건 생략·미검증 질문·연락처를 거부한다. tools=[]·store=false·Structured Outputs·HTTP 자동 재시도 없음·25초 전체 예산을 적용한다.
- 자유 입력을 OpenAI에 보내지 않고 선택 라벨·목적·조문 번호만 전달한다. 장기 질문에도 원문을 복사하지 않는다.
- 대화 쌍·정제 질문·완료 요청을 함께 저장하고 최종 인증·revision·철회 검사, 실패/취소 정리, 조회 시 isCurrent 재계산을 적용한다.
- 화면은 완료 대화·답변 방식·확인 질문·근거·과거 표시, 커서 조회, 응답 유실 복구, 새로고침 후 처리 중 요청 확인, 로그아웃 후 늦은 응답 차단을 제공한다.
- migration 0005_m10과 chat_usage로 회원별 20회/10분·전체 100회/UTC 하루 예약 한도를 기본 적용한다. 상담 삭제·재시작으로 한도가 초기화되지 않으며 재생은 차감하지 않는다. 임베딩 총비용 상한은 없다.

## 검증과 제한

백엔드 **219건**(실제 PostgreSQL 74건 포함), 프론트 **40건**, Ruff·포맷·타입·린트·빌드·OpenAPI/생성 타입 검사를 통과했다. 실제 api/web Docker 빌드 및 Alembic 모델 차이 없음도 확인했다. 시험은 provider 오류·refusal·부정확 주장/인용/조건·개인정보 미전송·위험/자료 부족·예약 한도·원자 저장·중복/실패·취소/상담 잠금·질문 삭제·최종 철회·페이지/복구·로그아웃을 포함한다.

실제 OpenAI 합성 평가 **12건 통과**: 승인된 설명 3건에서만 생성했고 나머지는 0회다. 최초 평가의 제35조 기대값은 M09의 외부 규정 미검증 제외 정책을 누락한 오류였다. 차단 동작을 유지하고 기대값을 수정했으며 최초 보고서도 보존했다. 별표는 참조 조문만 표시하지 않도록 전체 표/비고를 서버에서 추가했다.

로컬 HTTP 회원 흐름에서 생성 답변·제10조/별표 2·비고 보존, 동일 requestId 재생, GET 대화/요청 상태의 동일 표시, 맥락 변경 후 isCurrent=false, 합성 상담/질문 삭제를 확인했다. 초기 smoke의 정리 요청은 Content-Type 누락으로 거부되어 스크립트를 수정했다. 남은 합성 상담 1개와 인증 세션을 별도로 정리했다. 이번 작업의 합성 계정 3개는 서비스 개발 데이터로 남으며 실제 개인정보를 쓰지 않았다.

이 버전은 **검토 원문 선택·인용 방식**이다. 자유로운 의역·일반 한국어 추론·법률 판단을 검증했다고 주장하지 않는다. 설명에서 APPLICABLE은 LH 운영 적용을 의미하지 않는다. 본문 전체와 조건이 자동 검증되지 않으면 기본 안내로 전환한다. OpenAI 데이터 공유 혜택의 계정 자격/설정은 변경하지 않았다.
