# 진행 작업판 통합과 증거 색인 자동 생성

> 기록 ID: R012 · 기준일: 2026-10-18 · 환경: 저장소 문서·Python 표준 라이브러리 검사
> 관계: R011의 수동 색인 등록·별도 상태/작업 갱신 절차를 대체한다. R001~R011의 본문과 서비스 관측은 보존한다.
> 당시의 증거 기록이다. [현재 상태와 남은 작업](../current-status.md) · [갱신 방법](../README.md)

## 변경 이유와 대상

R011은 현재 판단·작업·증거를 분리했지만, 실행 한 번마다 기록·색인·최신 상태·작업 문서를 수동으로 맞춰야 했다. 기록의 ID·날짜·환경·관계도 색인에 중복 입력했다. 완료 기록을 분리한 뒤에도 읽고 수정할 문서 수가 늘어나는 문제가 남았다.

- `current-status.md`에 현재 상태·환경·외부 입력·남은 작업을 통합했다. 별도 작업 문서는 기존 단계 절 링크를 위한 고정 이동 안내만 유지한다. 활성 설계 문서는 현재 작업판 또는 당시 체크리스트 원본으로 직접 연결한다.
- 기록 파일의 제목과 기존 메타데이터를 원본으로 사용한다. `python scripts/check_progress.py --write`가 파일을 발견하고 정렬해 색인을 생성·검사한다. 색인 수동 등록·중복 입력을 없앴다. 기록 추가 때문에 이전 기록의 후속 링크를 수정할 필요도 없다.
- CI의 기존 명령은 쓰지 않고 비교만 한다. 생성 누락·색인 직접 편집을 검출하며 잘못된 원본에서는 `--write`도 색인을 덮어쓰지 않는다. 새 패키지·설정 형식·서비스는 추가하지 않았다.
- 현재 작업판의 작업/입력 ID·선행 조건과 완료 날짜/증거를 검증한다. 순환 선행 조건, 미완료 선행 작업을 둔 완료, 기록 ID와 다른 파일을 가리키는 링크도 검출한다. 별도 문서에 작업 표를 다시 만들면 실패한다.
- 끝난 작업의 ID·조건·결과는 기록에 보존하고, 현재 참조가 없어진 완료 작업은 작업판에서 제거한다. 현재 작업판은 미완료 작업과 단계별 요약을 중심으로 유지한다. 남은 작업이 0개인 경우도 허용한다.

## 검증과 증거

| 검사 | 결과 |
| --- | --- |
| `python scripts/check_progress.py --write` 및 읽기 전용 검사 | Markdown 47개·발견된 기록 12개·자동 생성 색인 일치; 선택 로컬 증거 링크 11개 제외 |
| 검사기 `unittest` | 13건 통과: 신규 기록 자동 발견, 생성 누락·직접 편집, 반복 생성 일치, 이동 후 경로 반영, 중복 ID/메타데이터/날짜, 오기된 인용, 완료 증거·선행 조건·단일 작업 원본 검사 |
| 원본이 잘못된 `--write` | 중복 ID를 검출하고 기존 색인 보존 |
| Ruff 검사·포맷 | `backend/pyproject.toml` 설정으로 검사기와 시험 파일 통과 |
| 기존 자료 대조 | 작업 시작 시점 R001~R011 파일 11개의 바이트 일치, 미완료 작업 8행 동일, M01~M13 절 링크 14개 유지 |

첫 회귀 실행에서 새 시험의 기본 Windows 인코딩과 누락된 탐색 링크 fixture가 실패했다. UTF-8을 명시하고 fixture의 필수 문서를 보완한 뒤 전체 13건을 통과했다. 실제 기록이나 검사 기준을 완화하지 않았다.

## 범위와 한계

문서 구조·관리 도구만 검증했다. 서비스 재배포·백엔드/프론트 회귀·외부 제공자 호출·원격 CI 실행은 수행하지 않았다. 기존 M13 구현 변경을 함께 수정하거나 서비스 상태를 새로 완료 처리하지 않았다. 자료 적용 제한과 M12 실제 운영 인수 조건은 그대로 남긴다.

자동 검사는 형식·참조·생성 일치·명시된 선행 조건을 확인한다. 문장 내용의 사실성이나 실제 환경의 최신 상태를 추론하지 않으며 현재 판단을 자동으로 완료 처리하지 않는다. 수동 갱신 대상은 새 증거 기록과 판단이 바뀐 현재 작업판 행이다.
